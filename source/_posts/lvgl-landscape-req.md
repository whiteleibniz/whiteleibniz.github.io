## 2. 需求拆解

**R1 表项改名 + 改行为**
`s_apps[]` 里「原厂桌面」→「切换桌面」；点击后不再 exec 原厂 launcher，改为**切到横屏放大菜单模式**。

**R2 横屏放大菜单（coverflow）**
- 逻辑上一排卡片：中间 1 个选中（放大 ~1.6x，不透明），左右各 1 个正常大小（~1.0x，半透明 ~0.6），更远的隐藏。
- 左右键导航时**带动画**：位置 + 缩放同步过渡，400ms 缓动（`cubic-bezier(.22,.61,.36,1)`）。
- 菜单项 = 现有桌面全部应用（含外部应用），沿用现有图标符号 + 背景色，不新增图片资源。

**R3 双向切换（toggle）**
- 竖屏网格桌面 → 点「切换桌面」→ 横屏放大菜单
- 横屏放大菜单 → 点同一项「切换桌面」→ 回竖屏网格桌面

**R4 键位**
| 键 | 横屏菜单模式下 |
|---|---|
| 点餐 114 / LEFT | 选中上一项（带动画） |
| 服务 102 / RIGHT | 选中下一项（带动画） |
| 福利 115 / ENTER | 启动选中应用 |
| 买单 116 / BACK | 回竖屏桌面（建议，待确认） |

**R5 不改的地方**
默认竖屏网格桌面的布局、焦点导航、外部应用加载、重启/关机确认弹窗，全部保持现状。

## 3. 需要你拍板的 4 件事

### Q1（最关键）横屏怎么呈现？
| | 方案 A：整屏旋转 90° | 方案 B：竖屏内横向放大带 |
|---|---|---|
| 做法 | 容器按 1280x720 布局，`transform_rotation=900` 旋到竖屏 | 不旋转，图标横排在 720 宽的屏幕中部 |
| 卡片大小 | 最大（300~520px） | 中等（选中 ~272px，两侧 170px） |
| 左右键语义 | 屏幕**上下**移动（反直觉，需把机器横过来看） | 屏幕**左右**移动（直觉一致） |
| 性能 | 旋转后每帧全屏重绘，768MHz 软渲染有掉帧风险 | 只重绘中间带，开销小 |
| 实现量 | 需处理旋转后的坐标/焦点/触摸换算 | 纯绝对定位 + 动画 |

**建议：方案 B**（机器竖装、键位语义一致、性能好；放大效果完全一样）。

### Q2 原厂桌面的入口还要不要？
改成「切换桌面」后，原厂安卓 launcher 就没有入口了。
- 选项①：彻底不要（推荐，原厂桌面在 LVGL 桌面上基本用不到）
- 选项②：保留，移到「设置」页里加一个「启动原厂桌面」按钮

### Q3 横屏菜单里放几个应用？
- 选项①：全部（19 项 + 外部应用），滑动较长
- 选项②：只放常用 N 项（你指定）

### Q4 买单键（BACK）在横屏菜单里做什么？
- 选项①：直接回竖屏桌面（推荐）
- 选项②：无效，只能靠选中「切换桌面」回去

## 4. 实现要点（确认后按此编码，不新建页面）

1. **不新建页面**，在 `launcher_page.c` 内加模式态（网格模式 / 横屏菜单模式），避免页面栈与焦点组进出不成对的问题（既有教训：焦点组共享，进出必须成对）。
2. **动画**：`lv_anim` 同时驱动 `x` 与缩放；缩放优先用 `lv_obj_set_style_transform_scale`（整体缩放，图标符号跟着放大，不用改字号）；不依赖 flex 重排，全部绝对定位。
3. **性能**：只创建/显示 3 个可见卡片，其余加 `LV_OBJ_FLAG_HIDDEN`；动画期间不触发整屏重绘。
4. **回退**：网格桌面的对象在横屏模式下隐藏而非销毁，切回时不重建，避免状态丢失。
5. 改完走既有部署流程（`make -j2` → 原子替换 → 重启），**验证由你手验**。
