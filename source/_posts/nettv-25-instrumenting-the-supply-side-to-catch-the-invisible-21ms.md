上一篇把连续播放拉到 386 秒，稳定性达标，却留下一笔**对不上的账**：AU 平均墙钟 62.6 ms，而所有分段计时器加起来只有 40.4 ms，**21.6 ms 没有任何计时器认领**。这次设备离线（RNDIS 未枚举、WiFi 也不通），没法上机测，那就干离线最该干的事——**把仪表装好**，让下一轮开机就能直接读出那 21.6 ms 是谁。

## 一、账为什么对不上

现有分段计时只覆盖了四块：段循环（bsOnMsg + 睡眠 + 9c 等）、snap、读帧、渲染。可是 worker 一轮 AU 里干的事远不止这些：

| 未计时区域 | 说明 |
|---|---|
| `rb_take()` | 环空时 `usleep(2000)` 空转等 dl 供数，2 ms 粒度平均白睡 1 ms |
| 取到 NAL 之后到 `DRIVE` 之前 | NAL 拷出、分片、补 out 队列、配额判断 |
| IDR 扎堆冷却 | `g_idr_gap_ms` 非零时主动 `usleep` |
| 帧间隔下限 | `g_fps_ms` 非零时的铺帧 `usleep` |

还有一个关键线索：**单段文件模式墙钟 = 剖析和，一毫秒不差**。差额只在"边下边播"的直播链路出现——所以嫌疑集中在"等数据"，而不是"算得慢"。

## 二、先靠默认配置排除掉三个嫌疑

不用上机就能砍掉一半候选，因为默认值摆在代码里：

- `g_gop_ms = 0`、`g_fps_ms = 0`（2026-10-19 定案：配额与铺帧默认全关）⇒ **GOP 预算跳过**和**帧间隔睡眠**在默认跑法下恒为 0；
- `g_idr_gap_ms` 只在相邻 IDR 间隔 < 1 s 时非零，而 GOP 约 2 s、解码还慢于实时 ⇒ **IDR 冷却**基本恒为 0；
- `NETTV_PTSSYNC` 默认关 ⇒ PTS 丢帧分支不参与。

于是默认路径下最大的一号嫌疑就是 **`rb_take()` 空转等供数**。但"最大嫌疑"不等于"已定罪"，所以这次的做法不是直接改它，而是**先把账闭合**。

## 三、仪器化做了什么（10-24 离线改动）

**worker 侧**：新增四个计时桶 `g_t_take / g_t_pre / g_t_cool / g_t_pace`，外加两个免费指标——

- **余差**：`墙钟 − (段循环 + snap + 读帧 + 渲染 + 取NAL + 准备 + 冷却 + 节拍)`，每 200 个 AU 打一次；
- **rb 深度**：每轮累计 `wpos − rpos`（未消费 NAL 数）的均值。

余差 ≈ 0 就说明 21.6 ms 已经落在某个桶里；余差仍然大，就说明还有第五处，继续二分。rb 深度则一眼区分两种世界：**深度长期≈0 ⇒ 消费者在等米（供数是瓶颈）；深度持续涨 ⇒ 消费是瓶颈**。

**dl 侧**：每段打一行 `[供数]`，四个数——

```text
[供数] 段N: 下载=Xms 入池=Yms 段间隙=Zms(EMA=…) rb深=D 背压=B
```

其中**段间隙**定义为"上一段最后 NAL 入池结束 → 本段开始入池"，也就是 rb 不再增长、worker 只能空转的那段窗口；它的主要成分是 `audio_feed` 的段节拍阻塞。段间隙大，就该让预取更深或提前拉段；下载耗时大，那是源限速，改代码没用。

**行为零改变**：`rb_take` 的空转粒度保留旧值 2000 µs，只新增 `NETTV_RBUS=N` 环境变量，等定位完成后可以直接做 2000/500/200 的 A/B，不用重新编译。

## 四、怎么读下一次的 perf 行

```text
[perf] AU#N 均值: 墙钟=… 段循环=… (bsOnMsg=… 睡眠=… 9c等=…)
       snap=… 读帧=… 渲染=… | 取NAL=… 准备=… 冷却=… 节拍=… | 余差=… rb深=… (ms)
```

判据表：

| 现象 | 结论 | 下一步 |
|---|---|---|
| 取NAL ≈ 21.6、rb深 ≈ 0 | 供数真是瓶颈（坐实） | 量化段间隙 → 提前拉下一段 / 加深预取 |
| 余差 ≈ 21.6、各桶都小 | 还有第五处没进桶 | 继续二分（多半是段尾收尾或丢帧分支） |
| rb深持续 > 几百 | 消费才是瓶颈 | 回到渲染 23.8 ms 那条线 |
| 余差 ≈ 0 且取NAL≈0 | 21.6 ms 是采样伪影 | 复核墙钟统计口径 |

## 五、方法论沉淀

1. **账对不上时先装仪表，不要先改代码**。直接把 `usleep(2000)` 改成 500 µs 也能"试试看"，但试完你不知道赢在哪儿、也不知道还有没有第二处。
2. **余差法**：把所有已知项加起来，把"未知"作为一个显式打印的量。未知量一旦变成数字，定位就从猜变成查。
3. **用默认值做静态排除**。三个候选根本不用上机——默认关闭的功能不可能在默认跑法里产生 20 ms。先读代码砍候选，再为上机留一个真正未知的量。
4. **供/消平衡的直读指标比计时更有解释力**：计时告诉你"等了多久"，rb 深度告诉你"为什么会等"。
