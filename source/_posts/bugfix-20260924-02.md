# bugfix_20260924_02 — 「切换桌面」横屏菜单白屏卡死（transform 渲染路径不可用）
> 关联提交：2341fad

> ⚠️ **本文结论已被 bugfix_20260924_03 推翻**：transform 在本机一直可用（`fc_game_page.c` 就是同一套用法）；
> 白屏真因是 **`transform_pivot` 未显式设为 50%**（默认是对象左上角 → 1280x720 画布绕左上角旋转后整体转出可视区）。
> 请以 03 为准；本文保留仅作“一次错误定性”的过程记录。

- 日期：2026-09-24
- 影响范围：`lv_pages/launcher_page.c`（新功能「切换桌面」→ 横屏放大菜单）
- 结论一句话：**这个 LVGL 构建里 `transform`（旋转/缩放）渲染路径不可用 —— 任何带 transform 的对象整个不绘制**；
  改为纯 `set_size` 动画后功能正常。

---

## 1. 现象与诉求

用户反馈：在桌面点「切换桌面」后 **白屏卡死**。

只读现场取证（`ssh_tools/_tmp/dbg_white.sh`）：

| 检查项 | 结果 |
|---|---|
| 进程 | `lvgl_demo` 存活，PPID=1，STAT=S |
| CPU | 0%（`top` 显示进程空闲） |
| 日志尾部 | 大量 `[HW Key] code=115/116` 与 `[nav] key=19/20/27`，**无 segfault / assert / fatal** |
| 结论 | 不是崩溃、不是死循环 —— 是**界面没画出来**（渲染层问题） |

## 2. 定位：先把设备救回来，再用「最小实验」缩小变量

1. **先回滚**：`lv_pages/launcher_page.c.bak_cover` 还原 → `make -j2` → 原子替换 → 重启。
   日志立即出现 `[fb] flush ... px0=ffdff3ff/ffe0f3ff`（桌面渐变底色），设备恢复可用。
2. **再做最小实验**：临时在 `onCreate` 末尾插入 `launcher_set_cover(true)`（自动进入菜单），
   这样不必依赖按键就能稳定复现，并用 `grab_screen.py` 抓帧逐层判断"谁没画出来"。

三次抓帧的结论递进：

| 版本 | 抓帧结果 | 推断 |
|---|---|---|
| 方案 A：容器 `1280x720` + `transform_rotation=900` | 整屏只剩父容器底色，**容器和卡片全部不见** | 大容器旋转被整体丢弃 |
| 方案 B 首版：容器不旋转，**卡片仍用 `transform_scale`** | 容器背景 + 顶部提示文字**正常画出**，**所有卡片消失** | transform 与对象大小无关，**只要带 transform 就不画** |
| 方案 B 修正版：**零 transform**，改 `set_size` 动画 | 卡片、图标、中文标题全部正常 | 根因确认 |

> 关键对照：同一个容器里，"没有 transform 的提示 label"画得出来，"有 transform 的卡片"画不出来 ——
> 变量被缩到只剩 transform 一项。

## 3. 根因

**该 LVGL 构建（`/root/lvgl_install` 预编译 liblvgl.a）的 transform 渲染路径在运行期不可用。**

- 早先我用静态符号法判断"支持"：`nm liblvgl.a` 里 `lv_draw_sw_transform` 在 **T 段**、
  `lv_obj_set_style_transform_rotation / scale_x / scale_y` 都在 → 结论"能链接、应该能画"。
  **这个判断只证明符号存在，不证明运行正确。**
- 最强旁证其实一直摆在源码里：`launcher_page.c` 的 `launcher_start_zoom()` 开头是
  `(void)target; return; /* transform disabled */`。`git log -S` 显示它是 **v1.0 初始提交就带的** ——
  当时被解读为"上游自己关掉了按下缩放效果"，**实际含义是"这台机器上 transform 画不出来，所以关掉"**。
  注释里的 "disabled" 是**证据**，不是噪音。

## 4. 修复

`lv_pages/launcher_page.c`（补丁脚本 `ssh_tools/_tmp/patch_cover3.py` + `patch_cover4.py` + `patch_cover5.py`）：

1. **弃用整屏旋转方案**（改为竖屏内横向放大带）：屏幕 720×1280，卡片横向排列，
   选中项 1.5×、左右各 1.0×；参数 `CARD=200 / GAP=250 / SEL=384 / SIDE=256`，
   在 720 宽内正好 `200 + 250 + 250 = 700` 铺满，不重叠。
2. **`cover_geom()` 彻底不用 transform**，改成尺寸动画：
   ```c
   lv_obj_set_size(it->cell, w, h);
   lv_obj_set_pos(it->cell, cx - w / 2, s_cover_cy - h / 2);
   lv_obj_set_size(it->box, bw, bw);        /* 色块跟着放大 */
   lv_obj_align(it->box, LV_ALIGN_TOP_MID, 0, 0);
   lv_obj_set_width(it->title, w);
   lv_obj_align(it->title, LV_ALIGN_TOP_MID, 0, bw + 6);
   ```
   `cover_anim_cb` 仍由一个 `lv_anim` 统一插值所有卡片的 `cx` 与 `scale`（320ms，ease_out）。
3. 删除 cell 上已无用的 `transform_pivot_*`。
4. 进入菜单时**补一次"隐藏 root 其它子对象"**（`ch2 != s_cover_root`）：
   网格是用 tileview 在 `onCreate` 后段创建的，只在进入时隐藏一次不够稳。

## 5. 验证

- 抓帧三连（`outputs/cover_check4~6.png`）：容器背景、顶部提示、中间放大卡片、两侧正常卡片、
  白色图标、中文标题（任务管理 / 切换桌面 / 相机）**全部正常**。
- 左右键导航：`[cover] built n=19 cx=360 cy=576` 后，按右键 11 次，选中项按预期逐个居中放大（截图 `cover_check5.png`）。
- 最终版（去掉临时的自动进入）部署后，桌面渐变底色正常、无崩溃。

## 6. 经验（反模式记录）

1. **"符号存在 ≠ 能力可用"**：`nm` 只能证明链接得过。涉及渲染/驱动能力时，**必须抓一帧实际画面**，
   或者在最小对象上做一次实验 —— 不要把静态符号当成能力验证的终点。
2. **上游注释要当证据读**：`/* transform disabled */` 若早点当真，就能省掉一整轮白屏事故。
   遇到 "disabled / not supported / FIXME" 先问"他们为什么关"。
3. **排查要给变量做减法**：本轮靠"临时自动进入 + 抓帧"，把"按键路径 / 焦点组 / 布局 / 渲染"四条线
   缩到"transform 有 vs 无"一条，才定住根因。
4. **故障先回滚**：改动一多，第一动作是恢复到可用基线（源文件 `.bak_*` + 原子替换），
   再在安全前提下做实验，避免用户长时间面对坏画面。
5. **USB 注入键验证不了物理键路径**：`/root/vhwkey2` 走 `usb_map`，与物理键语义不同；
   Enter/ESC 的实际手感必须由人手验（详见 §7）。

## 7. 遗留

- 进入菜单后按**物理福利键（Enter）选中「切换桌面」应返回**、按**物理买单键（ESC）应返回** ——
  这两条由用户实机确认（USB 注入的 ENTER/ESC 在本轮测试中未产生预期效果，但注入语义与物理键不同，
  不能用它下结论）。
- 卡片放大的只是色块与整体尺寸，**图标符号字号不随缩放变化**（无更大字号的图标字体，仅有 `montserrat_24`）；
  若需要"图标也变大"，需再引入一档大字号字体。
- 每次进入菜单会打印一行 `[cover] built n=.. cx=.. cy=..`（诊断用，保留便于以后排查）。
