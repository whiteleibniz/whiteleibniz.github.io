# bugfix_20260922_04 — 桌面「FM 收音机」图标渲染成空心方框

> **关联提交**：221fa7d

## 现象
在桌面新增「收音机」应用入口后，图标位置、底色（暖砖红 `0xe6614f`）、文字「收音机」
都正确，但**图标本身是一个空心方框（tofu）**，不是任何有意义的图形。

## 影响范围
- 只影响桌面「收音机」入口的图标。
- 其它已有应用图标全部正常（它们用的都是字体里确实存在的字形）。
- 不影响收音机页内部的功能与布局。

## 根因
`launcher_page.c` 里为 FM 选的图标码位在 `lv_font_cn_16` 中**根本没有对应字形**：

```c
#define RADIO_SYMBOL "\uF519"      /* FontAwesome broadcast-tower */
```

LVGL 渲染时 `lv_font_get_glyph_dsc()` 返回 not-found，就画成方框。
`U+F519` 属于 FontAwesome **5.x** 才加入的图标，而本机中文字体
`lv_font/font_cn.c`（`lv_font_cn_16`）只覆盖 **FontAwesome 4.x 的老子集**。

## 定位过程
1. 项目规范 §3.4 明确要求：**图标可用性必须验证字形存在，不能用"码位区间覆盖"或
   "看着像"来推断**。桌面截图里 `U+F519` 是方框，与规范警告一致。
2. 第一版探针 `glyph_probe.c` 只用了我**记忆里**的码位表，结果**标签对应关系是错的**
   （把 `0xF050` 当成 `LV_SYMBOL_PREV`、`0xF0C9` 当成 `LV_SYMBOL_LIST`）。
   → **教训：不要用人工映射的码位表去查字形。**
3. 重写 `glyph_probe2.c`：**直接用 `LV_SYMBOL_*` 宏本身**做输入，
   自己解 UTF-8 首字符得到码位，彻底消除人工映射错误。实测 52 项里
   **有字形 46 / 缺 6**，缺的正是 `F519 / F2CE / F7C0 / F8CE / F130 / F09E`。
4. 再写 `glyph_sweep.c` 扫 `U+F000..U+F8FF` 全区间，得到**权威清单：共 60 个图标**。
   **其中没有任何"电台 / 天线 / 电波"形状** —— 所以不能靠"换一个更像的码位"解决。
5. 编译 `glyph_probe*` 时踩到的坑：`lv_font_cn_16` 定义在应用源码
   `lv_font/font_cn.c` 里（不属于 `liblvgl.a`），且静态库 `liblvgl_thorvg.a`
   含 C++ 目标文件 → **必须用 `g++` 链接并直接带上 app 已编好的
   `build/lv_font/font_cn.o`**：
   ```
   g++ -O1 -o glyph_probe glyph_probe.c /home/lvgl_demo/lvgl_demo/build/lv_font/font_cn.o \
       -I/home/lvgl_demo/lvgl_demo -I/root/lvgl_install/include \
       -L/root/lvgl_install/lib -llvgl -llvgl_thorvg -lpthread -lm -ldl
   ```
   （用 `gcc` 会报 `undefined reference to lv_font_cn_16` 与一堆 `std::` 未定义。）

## 解决办法
从实测有字形的 60 个图标里，选语义最贴近"只能听声音的广播设备"、且未被现有
应用占用的 **`LV_SYMBOL_VOLUME_MAX`（`U+F028`，喇叭带声波，18x16）**：

```c
/* remote_src/launcher_page_patched.c */
/* 收音机图标：lv_font_cn_16 只含 60 个 FontAwesome 4.x 老图标，
 * 电台/天线/电波类（U+F519/F2CE/F7C0/F8CE/F09E/F130）全部无字形 → 会渲染成方框。
 * 实测有字形且语义最贴合"只能听声音的广播设备"的是喇叭 LV_SYMBOL_VOLUME_MAX (U+F028)。
 * 依据：设备端 glyph_sweep 全区间扫描（ssh_tools/glyph_sweep.c），不得凭记忆改。 */
#define RADIO_SYMBOL             LV_SYMBOL_VOLUME_MAX
```
（同时排查了现有 16 个应用的图标占用，避免撞车：DIRECTORY/EDIT/AUDIO/VIDEO/KEYBOARD/
SETTINGS/WIFI/BLUETOOTH/IMAGE/LIST/HOME/REFRESH/POWER/TINT/FILE 均已占用。）

## 验证
- 重新编译部署后取桌面截图：**「收音机」图标位置出现完整的喇叭图形**（有人眼在物理屏确认），
  不再是方框；焦点框也正确落在该格上。
- 留档图：`shots/radio_icon_fix_rgb.png`（正确字节序）。

## 经验教训
1. **图标可用性只能靠 `lv_font_get_glyph_dsc()` 实证，不能靠码位表或"FontAwesome 区间覆盖"推断。**
   本项目已因此踩过一次（`U+F519`）和一次探针自摆乌龙（人工码位映射错）。
2. **写探针时要用"权威来源"本身做输入**（这里是 `LV_SYMBOL_*` 宏），
   而不是自己转录一份映射表 —— 转录错误会让探针本身失去可信度。
3. **先确认"到底有没有解法"再动手**：扫描全区间后才知道这个字体根本没有电台形状，
   否则会一直在"换哪个码位"上浪费时间。
4. 在这个项目里编译小探针要复用的是**应用已编好的 `font_cn.o` + `g++`**，
   不要试图重新编译 27MB 的 `font_cn.c`，也不要指望 `liblvgl.a` 里有 CJK 字体。
