# bugfix_20260923_11 — GBA 退出卡黑屏，且 FC 被牽連（前端徹底分離）

| 項目 | 內容 |
| --- | --- |
| 發現時間 | 2026-09-23 |
| 修復時間 | 2026-09-23 |
| 模塊 | `extern/miniretro/*`（新增分離產物）、`lv_pages/gba_game_page.c` |
| 涉及版本 | 承接 bugfix_20260923_10 之後的現場 |
| 現象等級 | 高（GBA 退出不可用，且把原本正常的 FC 一起帶壞） |

## 1. 問題現象

用戶連續兩輪反饋：

1. 「退出邏輯還是有問題 **還是卡黑屏**」；
2. 「**把 GBA 的和 FC 的 miniretro 分開吧**，FC 原來版本都是好用的，被 GBA 修改的汙染了，
   導致 FC 的 miniretro 也不好用了，導致 FC 不能玩，退出莫名其妙。」

第 2 條是關鍵判斷：**兩個遊戲頁共用一個前端二進制，改 GBA 必然波及 FC**。用戶的訴求
（物理隔離）比"繼續在共用件上打補丁"更正確。

## 2. 影響範圍

- GBA 遊戲頁：退出後黑屏、退出鍵失效；
- FC 遊戲頁：被同一份 `miniretro` 的改動連帶影響，退出異常；
- 根因層面：任何"多個頁面共用一個可執行前端"的設計，都是這類跨模塊汙染的溫床。

## 3. 根因分析

### 3.1 ★ 等待循環設了"跑滿 N 秒就算退出"的上限（卡黑屏的直接原因）

`gba_wait_thread` 原來寫成"等夠一定時長就往下走"：

```c
for(int i = 0; i < 600; i++) {           /* 600 × 5ms = 3s（更早是 500ms + 5s 兩段） */
    ...等信號 / 等子進程退出...
    usleep(5 * 1000);
}
/* 循環結束後【無條件】恢復 UI */
hardware_keys_set_grab(true);
hardware_keys_set_interceptor(NULL, NULL);   /* ← 摘掉按鍵攔截器 */
app_runtime_set_lvgl_paused(false);          /* ← LVGL 搶回 fb0 */
```

**遊戲正常跑滿 3 秒**，就滿足"循環結束"這個條件，於是：

1. `hardware_keys_set_interceptor(NULL, NULL)` 把按鍵攔截器摘掉 → **買單鍵不再被攔截 → 退不出遊戲**；
2. `app_runtime_set_lvgl_paused(false)` 讓 LVGL 恢復繪製 → **父進程搶回 fb0，與還在跑的遊戲互相覆蓋**；
3. 兩者疊加 = 用戶看到的「**卡黑屏**」，且**只能重啟**。

**這正是"FC 沒問題、GBA 有問題"的分水嶺**：FC 頁用的是**阻塞式**
`while(waitpid(pid, &status, 0) < 0) {...}`（無上限），所以從來不誤判。
GBA 頁當初為了"快點恢復 UI"引入了上限，反而製造了 bug。

### 3.2 UI 恢復被綁在"子進程消失"上（把黑屏拉長）

本機內核回收 `/dev/input/eventX` 要幾百毫秒，實測**從發信號到收屍完成 ~455ms**，
而畫面在 ~40ms 就已交還。等收屍才恢復 UI，就白等了 400ms —— 這段時間屏幕全黑。

### 3.3 細節問題

- `gba_timer_cb` 只 `lv_obj_invalidate(lv_screen_active())` 一次，可能與 LVGL 恢復的
  時序錯開而被吞掉（標誌已消費、畫面卻沒畫回來）；
- `fb_restore()` 調 `FBIOPAN_DISPLAY` 後**不檢查結果**：若 `yoffset` 沒真的歸零，
  LVGL 會畫在第 0 頁而屏幕仍顯示第 1 頁 → **永久黑屏且完全靜默**，無法定位。

### 3.4 結構性根因：共用前端

FC 與 GBA 共用 `extern/miniretro/miniretro`。為 GBA 加的 **雙緩衝頁翻轉、pitch 尋址、
240×160 放行、音頻重採樣、退出信號處理** 全都落在這一份共用產物上。FC 因此被反覆牽連 ——
這是"改 A 壞 B"的必然結果，不是某一次改動沒寫好。

## 4. 修復方案

### 4.1 ★ 前端徹底分離（用戶方案）

| 產物 | 歸屬 | 說明 |
| --- | --- | --- |
| `extern/miniretro/miniretro` | **FC 專用** | `git checkout` 恢復成倉庫裡的原始版本，**此後永不重編、不被 GBA 改動觸碰** |
| `extern/miniretro/miniretro_gba` | **GBA 專用** | 含雙緩衝/pitch/240×160/音頻修正/退出修復 |
| `extern/miniretro/miniretro_gba.c` | GBA 源碼 | |
| `extern/miniretro/miniretro.c` | FC 源碼 | 已隨二進制一併還原成原始版本 |
| `extern/miniretro/build.sh` | — | **只編 `miniretro_gba`**，並在腳本頭寫明"不要再把產物寫成 miniretro" |

頁面側 `gba_find_bin()` 的首選路徑改為 `miniretro_gba`，並保留 `miniretro` 作為兜底：

```c
static const char *c[] = {
    GBA_EXTERN_DIR "/miniretro_gba",     /* ★ GBA 專用, 與 FC 隔離 */
    "/usr/local/bin/miniretro_gba",
    GBA_EXTERN_DIR "/miniretro",          /* 兜底: 尚未分離時仍可用 */
    "/usr/local/bin/miniretro",
    NULL
};
```

### 4.2 退出邏輯四項修復（只落在 GBA 頁）

1. **等待循環去掉時長上限**，只認兩個真實終止條件：

   ```c
   for(;;) {
       if(s_gba.exiting) break;                        /* 頁面發起退出: 畫面已交還 */
       pid_t r = waitpid(pid, &status, WNOHANG);
       if(r == pid || (r < 0 && errno == ECHILD)) { reaped = true; break; }   /* 自然退出 */
       usleep(5 * 1000);
   }
   ```

2. **新增 `exiting` 標誌：畫面一交還就恢復 UI，不等收屍**

   ```c
   /* gba_exit_to_list: */
   kill(pid, SIGTERM);
   usleep(120 * 1000);                     /* 等它翻回第 0 頁 + 清屏(實測 ~40ms 完成) */
   if(kill(pid, 0) == 0) kill(pid, SIGKILL);   /* 不等內核慢慢收 fd */
   s_gba.exiting = true;                   /* 立刻放行 UI; 收屍丟後臺 */

   /* gba_wait_thread: 未收屍則交後臺, 不阻塞畫面 */
   if(!reaped) { pthread_create(..., gba_reap_bg, ...); }
   ```

3. **恢復時連刷 3 幀**，不依賴單次 invalidate：

   ```c
   lv_obj_invalidate(lv_screen_active());
   for(int i = 0; i < 3; i++) lv_refr_now(NULL);
   ```

4. **`fb_restore()` 校驗翻頁結果**：只在 `yoffset != 0` 時才 pan，pan 後回讀確認，
   不歸零就打警告日誌（把"永久黑屏且無任何線索"變成可定位）。

同時給等待線程加了"仍是我這一局的 pid"判斷，避免上一局的線程醒來把新一局的狀態清掉。

| `miniretro_gba` md5 | `2b958d4f8fcec85b6f2668985848887b`（與上者不同 = 真正分離） |
| 體積 | `miniretro` 25648 B ／ `miniretro_gba` 35404 B |
| 編譯 | `make -j2` RC=0，0 error |

### 5.2 兩個前端各自實跑（`ssh_tools/split_verify.py`）

| | 前端 | 核心 | 畫面（非黑像素比） | 退出碼 | 收屍耗時 | 退出後 yoffset | 殭屍 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| FC | `miniretro`（原版） | fceumm | 0.600 ✓ | -15（被 SIGTERM 直接殺，原版行為） | 549 ms | 0 ✓ | 無 |
| GBA | `miniretro_gba` | mGBA | 0.380 ✓ | 0（優雅退出） | 575 ms | 0 ✓ | 無 |

- FC 退出碼 -15 符合"原版無信號處理"的預期；其頁面側在 120ms 後探測到進程已消失，
  直接恢復 UI —— 這正是用戶記憶中"FC 原來好用"的表現。
- GBA 側 `exiting` 標誌使 UI 在 ~125ms 即可恢復，收屍移到後臺；`yoffset` 歸零確認無黑屏隱患。
- 恢復後 `lvgl_demo` ×1 + `lvgl_watchdog` ×1，單實例，無殘留。

### 5.3 部署腳本的一處修正

`gba_redeploy.py` 用 `ps -o pid,args | grep '<名>'` 取 PID 來 kill，
而**該命令自身的命令行含這個字符串** → 匹配到承載命令的 `sh -c` → **殺掉自己的 SSH 連接**
（本次實測 `ConnectionResetError`）。已統一改為 `ps -o pid,comm`（承載 shell 的 `comm` 是 `sh`，
不會誤傷），見 `split_miniretro_gba.py` / `split_verify.py`。

## 6. 迴歸風險

- **`miniretro` 已還原為原版**：FC 側要的任何未來改動都必須**獨立**做，且不能再走
  "重編 miniretro" 這條路（`build.sh` 已只產 `miniretro_gba`）。若確需改 FC，
  應先 `git checkout` 一份到別的名字（如 `miniretro_fc`）再改，保持三者互不干擾。
- **GBA 側不再有"時長上限"**：等待線程在遊戲運行期間會一直循環（每 5ms 一次，開銷可忽略）。
  這是刻意選擇 —— 寧可多轉幾次，也不能誤判成"已退出"。
- `gba_reap_bg` / `onDestroy` 兩條收屍路徑都可能對同一 pid `waitpid`，雙方均已處理 `ECHILD`。
- 本次未改渲染與音頻鏈路，顏色、音質、幀率不應有變化。
