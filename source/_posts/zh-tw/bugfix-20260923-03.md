# bugfix_20260923_03 — GBA 遊戲點確認後無法打開（模擬器前端選型錯誤）

> **現象**：桌面「GBA遊戲」列表頁正常，選中 ROM 按確認鍵後**沒有任何畫面**（屏幕閃一下即回到列表），日誌只有一行 `Could not initialize video: fbcon not available`。
> **根因層**：模擬器前端選型 / SDL2 視頻後端（編譯期能力缺失）。
> **修復工作量**：新增 `lv_pages/gba_game_page.c`(+649)/`.h`(+17)；`lv_pages/launcher_page.c` +5/-0（新增入口）；設備端新增 `extern/miniretro/mgba_libretro.so`。
> **文件名**：`bugfix_20260923_03_GBA遊戲點確認後無法打開.md`
> **關聯提交**：（待提交後回填）
> **日期**：2026-09-23

## 現象

1. 桌面 → 「GBA遊戲」→ 列表正常顯示 `sdcard/game/gba/` 下的 `.gba` 與同名封面。
2. 選中 ROM 按確認鍵（福利鍵 115）：屏幕閃一下，**無遊戲畫面**，回到列表。
3. `stderr` 捕獲到 mGBA 的報錯：`Could not initialize video: fbcon not available`。

對照線索：**機器上原有的「FC 遊戲」應用一切正常**（同一 Launcher、同一全屏接管機制、同一個 `miniretro` 前端）。只有 GBA 打不開。

## 影響範圍

- **受影響**：GBA 遊戲應用（`gba_game_page`）。
- **不受影響**：FC 遊戲應用、桌面、其它頁面。
  原因：FC 走 `miniretro` **直接寫 `/dev/fb0`**，全程不碰 SDL；GBA 當時走 `mgba-sdl`，依賴 SDL。

## 根因

初版 `gba_game_page.c` 照搬 FC 框架，但把模擬器換成了 **mGBA 的 SDL 前端 `mgba-sdl`**，並在 `fork` 前設置：

```c
setenv("SDL_VIDEODRIVER", "fbcon", 1);
setenv("SDL_FBDEV", "/dev/fb0", 1);
```

而本機 SDL2（2.30.9, musl/arm）在**編譯期**就沒有啟用 `fbcon` 視頻後端——實測：

```
$ strings /usr/lib/libSDL2-2.0.so.0 | grep -iE 'fbcon|kmsdrm|x11|wayland|dummy'
  只有 wayland / x11 / kmsdrm / dummy，無 fbcon
$ ls /dev/dri
  不存在（kmsdrm 也無法工作）
```

所以 `SDL_VIDEODRIVER=fbcon` 指定的後端根本不存在，SDL 無可用視頻設備 → 初始化失敗 → 進程退出 → 表現為"打不開"。這是**編譯期能力問題**，改啟動參數無解。

## 定位過程

1. **先查現象**：桌面進程、`sdcard/game/gba/` 內容、`/tmp/lvgl_demo.log` 末尾——確認列表頁正常、ROM 存在、有報錯。
2. **彎路一（錯方向）**：一度懷疑"多個 `lvgl_demo` 實例搶 `/dev/fb0`""新二進制沒生效"。這些確實是當時存在的干擾（見經驗教訓），但**不是**本次打不開的根因。
3. **定位到 fbcon**：日誌裡 `fbcon not available` 是決定性線索。
4. **驗證 SDL2 能力**：`strings libSDL2 | grep 後端名` 無 `fbcon`；`/dev/dri` 不存在 → 證實無可用後端（**實測**，非推理）。
5. **確認正確路線**：讀 FC 的 `fc_game_page.c`，其啟動命令為
   `miniretro <core.so> <rom> [keymap.conf]`，`miniretro` 自行 mmap `/dev/fb0` 並直接繪製，**完全繞開 SDL**。

## 解決辦法

**放棄 `mgba-sdl`，改用從 mGBA 源碼編譯出的 libretro 核心 `mgba_libretro.so`，走與 FC 完全相同的 `miniretro` 直寫 fb 通道。**

- 設備端重新配置編譯（mGBA 的 `CMakeLists.txt` 支持 `BUILD_LIBRETRO`，會鏈接核心源文件而非只編空殼）：

  ```sh
  cd /home/GBAgame/mgba/build
  cmake -DBUILD_QT=OFF -DBUILD_SDL=ON -DUSE_LIBZIP=OFF -DUSE_EPOXY=OFF -DBUILD_LIBRETRO=ON ..
  make -j2        # 產出 build/mgba_libretro.so
  cp build/mgba_libretro.so /home/lvgl_demo/lvgl_demo/extern/miniretro/
  ```

- `gba_game_page.c` 的 `gba_launch()` 由 `execl(/usr/local/bin/mgba-sdl, "-f", ...)` 改為：

  ```c
  execl("extern/miniretro/miniretro",
        "miniretro", "extern/miniretro/mgba_libretro.so", path,
        "extern/miniretro/keymap.conf", (char *)NULL);
  ```

- `keymap.conf` 直接複用 FC 的那份（已含 A/B/L/R/START/SELECT/方向鍵）。

## 驗證

- **當時（僅到"能否加載"這一步）**：受控冒煙測試單獨運行
  `miniretro extern/miniretro/mgba_libretro.so <ROM> extern/miniretro/keymap.conf`，
  日誌給出 `core: mGBA 0.11.0`、`遊戲已加載 240x160, 59.73 fps`、`/dev/fb0 720x1280 @32bpp 已映射`。
  → **核心與前端鏈路可用**（但此時畫面仍未出，原因見 `bugfix_20260923_04`）。
- **最終用戶驗證**：見 `bugfix_20260923_05` 末尾（三篇是同一功能修復的連續三階段）。

## 經驗教訓

1. **嵌入式設備上，SDL2 的可用視頻後端是編譯期決定的，不能假設 `fbcon` 存在。**
   選前端前先做兩件事：`strings libSDL2*.so | grep 後端名`、`ls /dev/dri`。
2. **沒有 GPU / 沒有可用 SDL 後端時，"libretro 核心 + 前端直寫 fb"比"SDL 前端"穩得多**——
   它只依賴 `/dev/fb0`，不依賴 SDL/DRM/GPU 任何一層。
3. **別照搬"同一功能"的兄弟應用卻不核對底層依賴**：FC 能跑不代表 GBA 也能用同一種模擬器形態；
   FC 用的是 libretro 核心，GBA 初版卻選了 SDL 獨立前端，這是選型層面的不一致。
4. **干擾項要分清**：那一刻同時存在"多實例搶 fb0""新二進制未生效"等真實問題，但它們會**掩蓋**真正的根因，
   排查時要把"環境髒"和"功能壞"分開處理。
