# 展訊 SC9832A（spd-box）FM 收音機 —— LVGL 界面設計與交互規格

> **讀者對象**：實現收音機 App 的工程師 / AI 助手
> **使用方式**：先讀 §1–§2 拿到屏幕與硬件約束 → 按 §3 排圖標 → 按 §4 畫頁面 → 按 §5 拆功能優先級
> **核心價值**：所有尺寸按本機實測參數（720×1280 豎屏、`lv_font_cn_16` 行高 31px）算出，避免畫完再改行高；所有功能項均標註了對應的驅動 ioctl，避免設計出實現不了的交互

---

## 1. 設計約束（先定死，再畫頁面）

### 1.1 屏幕與字體硬參數

| 項目 | 值 | 來源 / 影響 |
|---|---|---|
| 分辨率 | **720 × 1280**（豎屏） | Framebuffer 實測；所有座標基於此 |
| LVGL 版本 | 9.6.0 | 用 `lv_obj_set_style_transform_rotation` 等 9.x API |
| 默認中文字體 | `lv_font_cn_16` | **禁止**用 `LV_FONT_DEFAULT`（Montserrat-14 無 CJK，會出方格豆腐塊） |
| `lv_font_cn_16` metrics | **line_height = 31px，base_line = 9px** | **關鍵**：名義 16px 字號，實際佔 31px 行高。按 16px 估算的佈局必然裁切中文 |
| 圖標字庫 | FontAwesome 碼位覆蓋區間 **61441 ~ 63650**（0xF001–0xF8A2） | 選圖標時必須落在該區間內 |
| 物理按鍵 | 點餐=114(LEFT)、服務=102(RIGHT)、福利=115(ENTER)、買單=116(BACK) | 導航/返回走按鍵，無觸摸屏時要能盲操作 |

> ⚠️ **本項目歷史教訓**：已有過因為按舊字體硬編碼行高（36/60px）導致中文被裁切的返工。
> 本規格內所有 y 座標均已按 **31px 網格**重算，實現時不要"視覺微調"成 16px 網格。

### 1.2 硬件能力邊界（決定 UI 能顯示什麼）

以下能力已由驅動符號**實測確認**（見 `FM收音打通_AI指導手冊.md` §2），UI 設計據此取捨：

| 驅動能力 | 對應 UI 元素 | 備註 |
|---|---|---|
| `TUNE` / `TUNE_NEW` | 手動調諧、列表跳轉頻點 | 直接定頻，響應快 |
| `SEEK` / `SEEK_NEW` | ◀◀ / ▶▶ 搜臺 | 找**下一個強信號**，非逐頻步進 |
| `SCAN` / `SCAN_NEW` / `STOP_SCAN` / `SCAN_GETRSSI` | 自動全頻掃描 + 進度條 + **可中斷** | 四個命令成套：`SCAN` 發起全掃、`SCAN_GETRSSI` 逐點取場強以驅動進度與去噪、`STOP_SCAN` 中途取消 |
| `GETRSSI` | 信號強度指示條 | 單頻點實時查詢 |
| `MUTE` / `SETVOL` / `GETVOL` | 靜音開關、音量滑條 | 注意：**仍有 `SETVOL`，但主輸出音量可能另走 ALSA**，見 §5 仲裁表 |
| `RDS_SUPPORT` / `RDS_ONOFF` | RDS 開關（上層關上層開） | 建議常開 |
| `rds_get_ps()` | **電臺名 PS（8 字符）** → 主頻點下的臺名 | RDS 最有價值的字段 |
| `rds_get_rt()` | **電臺文本 RT（64 字符）** → 滾動字幕 | 用於 second line 滾動 |
| `rds_get_pty()` | 節目類型（新聞/音樂/交通…） | 可顯示為小標籤 |
| `rds_get_af()` | 備用頻率 AF → **可自動切到信號更好的同套節目頻率** | 高價值增弎項，非 P0 |
| `rds_get_ct()` | 電臺時鐘 | 可作為狀態欄時間的可選來源 |
| `rds_get_ews()` | 緊急廣播 | 有合規意義，建議預留提示位 |
| `GETMONOSTERO` / `SETMONOSTERO` | 立體聲 ST 指示燈 | 單雙聲道指示 |
| `OVER_BT_ENABLE` | **FM 音頻改走藍牙** | §5.4 聲道仲裁的核心開關 |
| `ANA_SWITCH` / `I2S_SETTING` / `GET_I2S_INFO` | 模擬 cntl vs I2S 兩路音頻路徑選擇 | 實現一個即可，見 §5.4 |

> ⚠️ **需要實測確認（當前為待驗證項，不要當成事實）**
>
> 1. **FM 是否必須播耳機作天線**。芯片側 FM 射頻輸入常見做法是複用耳機線；本機 ALSA 拓撲裡有獨立的 FM 設備
>    （`01-04: Dfm sprd-codec-fm-4`），暗示可以不靠耳機。**必須先做完 §5.4 音頻路徑試驗再定方案**；
>    若最終需要耳機，UI 必須在無耳機時用全屏插畫提示"請插入耳機"（見 §4.1 狀態 Z2）。
> 2. RDS 解析函數雖然在驅動裡，但**是否已由用戶態提供數據結構**尚無頭文件佐證，`Struct number` 待定。
> 3. 音量 `SETVOL` 與實際主輸出音量的關係：可能只是 FM 模塊內部增益，主管量另在 ALSA。

## 2. 系統定位：收音機在整個 App 裡的位置

```
桌面 launcher（g_launcher_page）
   ├── 狀態欄：左=時間  右=電池 / WiFi / 藍牙圖標
   │
   └── 應用網格 s_apps[]（第 3 行第 2 個）
         ├── … 網絡（LV_SYMBOL_WIFI,  0x56ccf2）
         ├── 藍牙（LV_SYMBOL_BLUETOOTH, 0x1e88e5）   ← 索引 7
         ├── 收音機（新）                            ← 索引 8 ★ 緊跟藍牙
         ├── 圖庫
         └── …
                 │ 點擊
                 ▼
        收音機頁 g_radio_page（新增）
                 │ 後臺常駐播放、返回桌面不停臺
                 ▼
        FM daemon（新增，/tmp/fm_ctl.sock）
                 │ ioctl / AT → /dev/fm
                 ▼
        Marlin2 芯片 FM 部件（與 WiFi/藍牙共享 SDIO）
```

**與其他既有頁面的關係**：

| 頁面 | 關係 | 交互 |
|---|---|---|
| 網絡頁 `g_network_page` | **前置依賴** | FM 固件隨 WiFi 一次下載好；WiFi 未拉起 ⇒ FM 不可用（須灰化圖標或彈提示） |
| 藍牙頁 `g_bluetooth_page` | **聲道互斥** | A2DP 播放時開 FM ⇒ 需上層仲裁，見 §5.4 |
| 音樂/視頻頁 | **聲道互斥** | 本地播放與 FM 互斥 |
| 桌面 `g_launcher_page` | 返回關係 | 返回不停臺，見 §5.5 |

## 3. 入口設計與圖標（要求 ①）

### 3.1 桌面網格排布

當前 `s_apps[]`（`lv_pages/launcher_page.c` 第 94 行起）順序：

| 索引 | 名稱 | symbol | 背景色 |
|---|---|---|---|
| 6 | 網絡 | `LV_SYMBOL_WIFI` | `0x56ccf2` |
| **7** | **藍牙** | `LV_SYMBOL_BLUETOOTH` | `0x1e88e5` |
| **8** | **收音機（新增）** | 見 §3.2 | `0xe6614f`（建議） |
| 9（原 8） | 圖庫 | … | … |

> **視覺順序由 `s_apps[]` 數組順序決定**（網格遍歷用 `sizeof(s_apps)/sizeof(s_apps[0])`，見 `launcher_page.c:985` 與 `:1055`），
> 所以只要在數組裡把它放在藍牙條目之後，就自動排到藍牙後面。

### 3.2 三處代碼改動（必改，缺一不可）

**（1）枚舉** —— `launcher_page.c` 第 40 行附近的枚舉：

```c
    LAUNCHER_APP_BLUETOOTH,
    LAUNCHER_APP_RADIO,             /* ★ 新增 */
    LAUNCHER_APP_GALLERY,
```

> ⚠️ **建議不要把枚舉插在有隱式連續值的中間**：上面寫法會讓 `GALLERY` 及其後各項的數值整體 +1。
> 若擔心有狀態持久化了舊數值，更穩的寫法是**加在枚舉末尾**（`LAUNCHER_APP_EXTERN = 1000` 之前），
> 視覺順序仍由 `s_apps[]` 數組控制。兩種方式二選一，選定後全項目統一。

**（2）數組** —— `s_apps[]`：

```c
    { LAUNCHER_APP_BLUETOOTH, "藍牙",   LV_SYMBOL_BLUETOOTH, 0x1e88e5 },
    { LAUNCHER_APP_RADIO,     "收音機", RADIO_SYMBOL,       0xe6614f },  /* ★ 新增 */
```

**（3）跳轉分支** —— `open_app` 的 switch：

```c
        case LAUNCHER_APP_RADIO:
            lv_start_activity(&g_radio_page, LV_PAGE_FLAG_DEFAULT, LV_PAGE_ANIM_SLIDE_LEFT, 220);
            break;
```

標準跳轉寫法與其他頁面一致（`lv_start_activity(&g_xxx_page, LV_PAGE_FLAG_DEFAULT, LV_PAGE_ANIM_SLIDE_LEFT, 220)`）。

### 3.3 圖標選型

LVGL 內置符號裡**沒有收音機 dedicated 符號**。三個候選：

| 候選 | 碼位 | 十進制 | 是否在已確認覆蓋區間 | 評價 |
|---|---|---|---|---|
| **broadcast-tower** | `U+F519` | 62745 | ✅ 在 61441–63650 內 | **推薦首選**：塔形，識別度高 |
| podcast | `U+F2CE` | 62158 | ✅ | 備選，偏"播客"語義 |
| satellite-dish | `U+F7C0` | 63424 | ✅ | 備選，偏"衛星"語義 |
| ~~radio~~ | `U+F8CE` | 63702 | ❌ **超出 63650** | **禁止使用**，會渲染成豆腐塊 |

```c
/* 建議放在 radio_page.h 或公共 symbols 頭裡 */
#define RADIO_SYMBOL "\uF519"   /* broadcast-tower，待 §3.4 驗證後固化 */
```

**背景色**建議 `0xe6614f`（暖磚紅）：桌面現有色板裡藍色系已被網絡/圖庫/藍牙大量佔用，紅色系只有關機（`0xe74c3c`）和音樂（`0xeb5757`）；暖磚紅與這三者都不撞色，且暖色調符合"收音機/廣播"的常規心理暗示。

### 3.4 圖標驗證（**交付前必做，缺此步不算完成**）

區間覆蓋是間接證據，**碼位是否有具體字形必須實測**：

```sh
# 方法：寫個最小 LVGL 測試頁渲染該碼位，截圖看是字形還是豆腐塊
# 參考本項目既有驗證思路：寫已知值 → 出圖 → 人眼確認
```

> ⚠️ **禁止用"渲染出來看著像"自證**：這與本項目顯示類問題的排障紀律一致
> （"抓數據→按假設解碼→看起來對"不是證據）。必須**人眼在物理屏上確認**是塔形圖案而非方框。
>
> 若 `U+F519` 缺字形 → 退化方案：用 32×32 PNG 資源，或退而用 `LV_SYMBOL_AUDIO`（與"音樂"語義衝突，不推薦）。

### 3.5 設置頁排布

設置頁 `g_settings_page` 內**建議新增兩項**（跟隨藍牙項之後）：

| 控件 | 作用 |
|---|---|
| 開關「收音機開機自啟」 | 控制 `fm_radio.start` 是否隨系統起來（默認關，見 §5.5） |
| 條目「收音地區與頻段」 | 中國 87.5–108.0 MHz / 步進 100 kHz；留口給日本 76–90 MHz、歐規 50 kHz 步進 |

> 這兩項屬 **P2**，可在 P0/P1 完成後再補。

| B | 頻段模式條 | 80 – 111 | 31 | `FM` + `87.5 – 108.0 MHz` + `100 kHz` + ST 立體聲標 |
| C | 當前頻點 | 120 – 232 | 112 | **大字號** `97.4` + `MHz`；下方 RDS 臺名 PS |
| D | 刻度尺 | 244 – 340 | 96 | 頻率刻度 + **調諧指針** + 收藏頻點標記 |

### 4.2 分區詳細規格

#### A. 標題欄（0–72）

| 元素 | 位置 / 尺寸 | 說明 |
|---|---|---|
| 返回按鈕 | x=0, 56×56，`LV_SYMBOL_LEFT` | 點擊 → 返回桌面但**不停臺**（見 §5.5） |
| 標題 | 居中，`lv_font_cn_16` | 「收音機」 |
| 耳機狀態 | x = 720-56 | 無耳機顯示 🎧 劃掉；有耳機隱藏。依賴 §1.2 待驗證項 1 |
| 聲道指示 | 緊鄰左側 | 小標「耳機 / 揚聲器 / 藍牙」，與 H 區聯動，點擊可彈聲道切換窗（P2） |

#### B. 頻段模式條（80–111）

單行 31px，四段信息：`[FM] [87.5 - 108.0 MHz] [100 kHz] [ST]`。
ST 立體聲標僅在 `GETMONOSTERO` 返回立體聲時點亮，作為 RDS 可用性的間接指示。

#### C. 當前頻點（120–232）—— **視覺焦點**

| 元素 | 規格 |
|---|---|
| 頻率數字 | **48px 加粗**（需引入或用現有最大字號；若 `lv_font_cn_16` 無此尺寸，用 LVGL 縮放變換或新增點陣字號） |
| 單位 `MHz` | 16px，隨數字右對齊 |
| RDS 臺名 | 16px 單行，取 `rds_get_ps()`，無 RDS 時顯示空白或「—」 |
| 字號提醒 | 該區域高度 112px，容納一行 48px（佔 62px 行區）+ 一行 16px（31px）+ 調節餘量 |

> ⚠️ 48px 中文字號**必須先用實際情況驗證**（`lv_font_cn_16` 為 16px 點陣）。
> 若該字號不可用，兩種替代方案：
> 一是用 LVGL 的 `lv_obj_set_style_transform_scale()` 對數字做放大（點陣字體放大後有鋸齒，效果一般）；
> 二是新增一個 48px 中文/數字點陣字號（效果最好，但增加固件體積）。此項屬 P1 依賴，需實測後定。

#### D. 刻度尺與調諧指針（244–340）—— **核心交互件**

- **刻度生成**：按當前頻段上下界與步進（默認 87.5–108.0 MHz / 100 kHz）計算，繪製主刻度（每 1 MHz）+ 次刻度（每 0.5 MHz）。
- **指針**：倒三角，x 由當前頻點線性映射；文件 `lv_obj_set_x()` 更新，切換 ANIM 200ms。
- **收藏標記**：在對應頻點 x 上畫 ★ 形小標記，標記位置隨收藏列表實時增刪。
- **交互**：
  - 拖動 / 左右劃 → **頻點微調**（每 move 10px ≈ 100 kHz），實時 `TUNE` 更新 C 區數字。
  - 點擊刻度某位置 → 直接 `TUNE` 到該頻點。
  - 物理 LEFT/RIGHT 鍵（114/102）→ ±100 kHz 微調（觸摸屏外的可達性必備）。

#### E. 信號強度與 RDS 文本（352–413）

| 元素 | 來源 | 規格 |
|---|---|---|
| RSSI 五格信號條 | `GETRSSI` | 輪詢週期建議 500ms；強弱閾值**需實測標定**（當前無樣本，先在實現時用 `/tmp/fmtest` 打印原始值找分界線） |
| RT 滾動字幕 | `rds_get_rt()` | 64 字符，超寬時滾動；無 RDS 隱藏 |

> ⚠️ RSSI 閾值必須**實測標定**，不要照搬網上通用的 `-85dBm` 之類數值——本機 `GETRSSI` 返回的是驅動原始值，量綱未知。

#### F. 控制區（430–590）

五行位 3 類按鈕（建議使用 96×96 圓形按鈕，縱向居中一 ribbon）：

| 按鈕 | 圖標 | 行為 | 驅動調用 |
|---|---|---|---|
| 上一頻點 ◀◀ | `LV_SYMBOL_PREV` | `SEEK` down（找下一個強信號） | `SEEK(dir=0)` |
| 搜索 ⟲ | `LV_SYMBOL_REFRESH` | 短按=單次 seek；**長按=自動全頻掃描** | `SEEK` / `SCAN` |
| 靜音 🔇 | `LV_SYMBOL_MUTE` | 切換 FM 靜音 | `MUTE` |
| 下一頻點 ▶▶ | `LV_SYMBOL_NEXT` | `SEEK` up | `SEEK(dir=1)` |

> 自動掃描：**長按 ⟲ ≥ 800ms** 觸發，掃描期間按鈕變為「停止」，`STOP_SCAN` 可中斷。
> 掃描總線也建議其餘按鈕 disabled，避免狀態機混亂。

#### G. 收藏頻道列表（606–1110）

`lv_list` 實現，每行高度 **62px**（兩行文字各 31px）：

```
┌───────────────────────────────────┐
│ ★  97.4 MHz                  [✕]  │
```

### 4.4 頁面註冊範式（嚴格遵守既有約定）

```c
extern lv_page_t g_radio_page;

lv_page_t g_radio_page = {
    .root = NULL,
```

### 5.3 FM daemon 接口（鏡像 `bt_user_daemon` 的既有範式）

藍牙 daemon 用的是 unix socket + 純文本命令（發 `state` / `on` / `off`，回 `OK ...\n`），FM 建議完全照抄該範式：

| 項目 | 藍牙（既有，參照） | FM（新增，建議） |
|---|---|---|
| socket 路徑 | `/tmp/bt_ctl.sock` | **`/tmp/fm_ctl.sock`** |
| 權限 | `chmod(SOCK_PATH, 0666)` | 同 |
| 協議 | 文本命令 + `\n` 結尾，回 `OK <payload>\n` | 同 |
| 典型命令 | `state` / `on` / `off` / 掃描相關 | `state`、`open`、`close`、`tune <freq_khz>`、`seek <0|1>`、`scan`、`stopscan`、`rssi`、`vol <n>`、`mute <0|1>`、`rds` |

> 🔒 **必須設超時**：做 socket I/O 的 LVGL 定時器回調**必須** `SO_RCVTIMEO` / `SO_SNDTIMEO`（建議 200ms），
> 否則 daemon 卡住會直接凍結 UI 線程。這是本項目藍牙頁踩過的硬教訓。

### 5.4 聲道仲裁（FM / A2DP / 本地播放互斥）—— 重點設計

三種 FM 音頻輸出路徑由驅動暴露：

| 路徑 | 開關 | 適用場景 | 優先級建議 |
|---|---|---|---|
| **模擬/內部 codec** | `ANA_SWITCH` | 本機揚聲器 / 耳機直出 | 默認 |
| **I2S** | `I2S_SETTING` / `GET_I2S_INFO` | 需走外部 codec 時 | 備選（**需實測確認是否可用**） |
| **Over BT** | `OVER_BT_ENABLE` | FM 聲音從藍牙耳機/音箱出 | 藍牙已連接時可選 |

**仲裁規則建議**（在 LVGL 主進程實現單一"音頻焦點"模塊，daemon 只管設備）：

| 當前佔用者 | 新申請者 | 處理 |
|---|---|---|
| 空閒 | FM | 直接獲取；按 §5.4 表選默認路徑（耳機插入→耳機，否則揚聲器） |
| 空閒 | A2DP | 直接獲取 |
| FM | A2DP | **FM 自動 mute（不 close）**，A2DP 結束後詢問是否恢復 FM |
| A2DP | FM | 彈確認框：「藍牙正在播放，是否切到收音機？」→ 同意則暫停/斷開 A2DP 後 FM 接管 |
| 本地播放（音樂/視頻） | FM | 停止本地播放 → FM 接管 |
| FM | 本地播放 | FM mute → 本地播放接管 |

> ⚠️ `OVER_BT_ENABLE` 是本設計的**關鍵不確定項**：它到底是把 FM 音頻"送給已連接的藍牙設備"，
> 還是"允許 FM 與 BT 共存"，尚未經讀碼確認。
> **實現前必須先用最小程序試探該 ioctl 的行為**，再寫仲裁邏輯。這條不確認就動手，很可能會錯測。

### 5.5 後臺播放與息屏保持

| 需求 | 實現要點 |
|---|---|
| 返回桌面繼續播放 | `onPause` 只停 UI 定時器/回調，**不調 close、不靜音**；播放狀態由 daemon 持有，與頁面生命週期解耦 |
| 頁面徹底銷燬 | `onDestroy` 同樣不停臺（理由同上）；只有用戶顯式按關閉或關機才 stop |
| 息屏保持播放 | 息屏由系統背光管理；FM 是 daemon 在播，不依賴 LVGL 心跳。**需實測**：確認息屏不會觸發 `fm_suspend`（驅動裡有 `fm_suspend` / `fm_resume`，是被 PM 掛起的入口，務必驗證系統 suspend 時 FM 是否掉臺） |
| 開機自啟 | 參考既有 `bt_user_daemon` 的 openrc 自啟寫法；自啟前必須先確認 WiFi 鏈已拉起（固件依賴，見 §5.2 第 0 步） |

> ⚠️ 驅動符號表裡有 `fm_suspend` / `fm_resume` 兩個**靜態**函數（`t` 而非 `T`），說明驅動實現了 dev_pm_ops。
> 系統掛起時 FM 很可能會被一起掛起。若產品要求息屏續聽，需要額外處理（wakelock 或禁止 suspend），此項**必須實測**，不可假定。

### 5.6 狀態持久化

建議路徑 `/etc/fm_radio.conf`（或沿用項目既有配置存放約定），JSON/INI 二選一：

| 字段 | 說明 |
|---|---|
| `last_freq` | 上次收聽頻點（kHz），開機恢復到該頻點 |
| `volume` | 上次音量 |
| `muted` | 靜音狀態 |
| `rds_on` | RDS 開關（建議常開） |
| `band/region` | 地區頻段（P2） |
| `favorites[]` | 收藏列表：`{freq, name}` |

寫入時機：退出程序、切換頻點後 debounce 1s、增刪收藏立即寫。

## 6. 一句話總結

> **收音機不是一個"從零寫一個 FM 協議棧"的活兒**：
> 本機 **Marlin2 芯片的 FM 部件 + `marlin_fm.ko` 驅動已經現成在跑**（`/dev/fm` 也已經在 `/proc/misc` 註冊），
> 真正的工作量集中在**三件事**——寫一個鏡像 `bt_user_daemon` 範式的 FM daemon 把 ioctl 包裝成 socket 命令、
> 按 31px 行高網格畫出收音機頁、以及做好 **FM / A2DP / 本地播放的聲道仲裁**。
> 動手前先跑完 §1.2 標註的三項待驗證確認，尤其是"要不要播耳機當天線"和 `OVER_BT_ENABLE` 的真實語義。
