# bugfix_20260923_03 — GBA games cannot be opened after pressing confirm (wrong emulator front-end selection)

> **Symptoms**: The desktop "GBA Games" list page is normal, but after selecting a ROM and pressing the confirm key, **no picture appears at all** (the screen flashes once and returns to the list), and the log has only one line: `Could not initialize video: fbcon not available`.
> **Root cause layer**: Emulator front-end selection / SDL2 video backend (missing compile-time capability).
> **Fix effort**: New `lv_pages/gba_game_page.c` (+649) / `.h` (+17); `lv_pages/launcher_page.c` +5/-0 (new entry); new device-side `extern/miniretro/mgba_libretro.so`.

> **Date**: 2026-09-23

## Symptoms

1. Desktop → "GBA Games" → the list correctly displays the `.gba` files and same-named cover images under `sdcard/game/gba/`.
2. Select a ROM and press the confirm key (the 福利 key, key 115): the screen flashes once, **no game picture appears**, and it returns to the list.
3. `stderr` captures mGBA's error: `Could not initialize video: fbcon not available`.

Comparison clue: **the pre-existing "FC Games" application on the machine works perfectly** (same Launcher, same full-screen takeover mechanism, same `miniretro` front-end). Only GBA cannot be opened.

## Scope of impact

- **Affected**: The GBA game application (`gba_game_page`).
- **Not affected**: The FC game application, the desktop, other pages.
  Reason: FC goes through `miniretro` **writing `/dev/fb0` directly**, never touching SDL at all; GBA at the time went through `mgba-sdl`, which depends on SDL.

## Root cause

The initial version of `gba_game_page.c` copied the FC framework but switched the emulator to **mGBA's SDL front-end `mgba-sdl`**, and set the following before `fork`:

```c
setenv("SDL_VIDEODRIVER", "fbcon", 1);
setenv("SDL_FBDEV", "/dev/fb0", 1);
```

However, this machine's SDL2 (2.30.9, musl/arm) did **not** enable the `fbcon` video backend **at compile time** — as measured:

```
$ strings /usr/lib/libSDL2-2.0.so.0 | grep -iE 'fbcon|kmsdrm|x11|wayland|dummy'
  只有 wayland / x11 / kmsdrm / dummy，无 fbcon
$ ls /dev/dri
  不存在（kmsdrm 也无法工作）
```

So the backend specified by `SDL_VIDEODRIVER=fbcon` does not exist at all; SDL has no available video device → initialization fails → the process exits → manifesting as "cannot be opened". This is a **compile-time capability problem** that cannot be solved by changing startup parameters.

## Diagnosis process

1. **First check the symptoms**: the desktop process, the contents of `sdcard/game/gba/`, and the end of `/tmp/lvgl_demo.log` — confirm that the list page is normal, the ROM exists, and there is an error.
2. **Detour one (wrong direction)**: At one point we suspected "multiple `lvgl_demo` instances grabbing `/dev/fb0`" and "the new binary not taking effect". These were indeed interferences present at the time (see Lessons Learned), but they were **not** the root cause of this particular failure to open.
3. **Locate fbcon**: `fbcon not available` in the log is the decisive clue.
4. **Verify SDL2 capabilities**: `strings libSDL2 | grep backend names` shows no `fbcon`; `/dev/dri` does not exist → confirmed there is no available backend (**measured**, not inferred).
5. **Confirm the correct route**: Read FC's `fc_game_page.c`, whose launch command is `miniretro <core.so> <rom> [keymap.conf]`; `miniretro` itself mmaps `/dev/fb0` and draws directly, **completely bypassing SDL**.

## Solution

**Abandon `mgba-sdl` and instead use the libretro core `mgba_libretro.so` compiled from the mGBA source, going through exactly the same direct-fb channel via `miniretro` as FC.**

- Reconfigure and compile on the device (mGBA's `CMakeLists.txt` supports `BUILD_LIBRETRO`, which links the core source files instead of compiling only an empty shell):

  ```sh
  cd /home/GBAgame/mgba/build
  cmake -DBUILD_QT=OFF -DBUILD_SDL=ON -DUSE_LIBZIP=OFF -DUSE_EPOXY=OFF -DBUILD_LIBRETRO=ON ..
  make -j2        # 产出 build/mgba_libretro.so
  cp build/mgba_libretro.so /home/lvgl_demo/lvgl_demo/extern/miniretro/
  ```

- `gba_launch()` in `gba_game_page.c` is changed from `execl(/usr/local/bin/mgba-sdl, "-f", ...)` to:

  ```c
  execl("extern/miniretro/miniretro",
        "miniretro", "extern/miniretro/mgba_libretro.so", path,
        "extern/miniretro/keymap.conf", (char *)NULL);
  ```

- `keymap.conf` directly reuses FC's copy (it already contains A/B/L/R/START/SELECT/direction keys).

## Verification

- **At the time (only up to the "can it load" step)**: a controlled smoke test running `miniretro extern/miniretro/mgba_libretro.so <ROM> extern/miniretro/keymap.conf` on its own produced the log entries `core: mGBA 0.11.0`, `游戏已加载 240x160, 59.73 fps`, and `/dev/fb0 720x1280 @32bpp 已映射`.
  → **The core and front-end chain is usable** (but at that point the picture still had not appeared; see `bugfix_20260923_04` for the reason).
- **Final user verification**: see the end of `bugfix_20260923_05` (the three articles are three consecutive stages of the same feature fix).

## Lessons learned

1. **On embedded devices, the available video backends of SDL2 are decided at compile time; you cannot assume `fbcon` exists.**
   Before selecting a front-end, do two things: `strings libSDL2*.so | grep backend names` and `ls /dev/dri`.
2. **When there is no GPU / no usable SDL backend, "libretro core + front-end writing fb directly" is far more robust than "SDL front-end"** — it depends only on `/dev/fb0` and on neither SDL, DRM, nor GPU at any layer.
3. **Do not copy a sibling application with "the same function" without checking the underlying dependencies**: FC being able to run does not mean GBA can use the same emulator form; FC uses a libretro core, whereas GBA's initial version chose an SDL standalone front-end — this is an inconsistency at the selection level.
4. **Distractors must be separated**: at that moment there were simultaneously real problems such as "multiple instances grabbing fb0" and "the new binary not taking effect", but they would **mask** the true root cause; during investigation, handle "a dirty environment" and "broken functionality" separately.
