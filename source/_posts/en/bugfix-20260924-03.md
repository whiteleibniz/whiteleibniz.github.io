# bugfix_20260924_03 — "Switch desktop" landscape shows only half (the root cause is the pivot not being set, not transform being unavailable)
> Related commit: 2341fad

- Date: 2026-09-24
- Scope of impact: `lv_pages/launcher_page.c` (landscape desktop), `main.c` (rollback), `lv_pages/launcher_page.h`
- **This article also overturns** the conclusion of `bugfix_20260924_02`.
- One-sentence conclusion: **transform has always been available on this device**; 02's white-screen root cause was
  **`transform_pivot` not being set** (the default is the object's top-left corner; the 1300x720 canvas rotates 90° around its top-left corner and moves entirely out of the visible area).
  The correct approach for landscape = exactly the same as `lv_pages/fc_game_page.c`: 1280x720 logical canvas + `lv_obj_center` +
  `transform_pivot=50%` + `transform_rotation=900`.

---

## 1. Symptom and requirement

- After 02, landscape switched to "full-screen transposition at the flush layer" (`lv_hardware/fb_rotate.c` + changing the display resolution at runtime).
- User feedback: **"the desktop only shows half"**, together with a request to **"implement landscape display with reference to the FC game page source"**.

The user's hint is itself the correct answer: `fc_game_page.c` is **a landscape page long in use in the same project**,
and it uses exactly `transform_rotation`.

## 2. Localization: why 02 concluded "transform is unavailable"

Put the two implementations side by side and diff them; the difference is only one line:

| | 02's failing version | `fc_game_page.c` (always normal) |
|---|---|---|
| Logical canvas | 1280x720 | 1280x720 |
| `lv_obj_center(canvas)` | present | present |
| **`transform_pivot_x/y = lv_pct(50)`** | **absent** | **present** |
| `transform_rotation` | 900 | 900 |
| Parent container | page root | page root |

The answer was written in `fc_game_page.c`'s comment all along:

> 旋转支点必须显式设成中心！这台 LVGL style 默认的 `transform_pivot` 是对象左上角，
> 不设的话画布会绕左上角转出屏幕外，**整页一个像素都看不到**。

**"整页一个像素都看不到" = the white screen observed in 02**. The root cause was in the comment all along.

## 3. Root cause

1. **Direct cause**: `transform_pivot` not set → the default pivot = the object's top-left corner. After the 1280x720 canvas rotates 90° around its top-left corner,
   the visible area falls outside the screen → it looks like "the container and the cards are all gone".
2. **02's misjudgment chain**:
   - Observed "objects with transform are not drawn" (the observation was correct);
   - but escalated it to a **device-level characterization** "this device's transform rendering path is unavailable" (the conclusion was wrong);
   - the counterexample was in the same repository (`fc_game_page.c`), **but nobody searched for it at the time**.
   - So the correct approach was abandoned, and full-screen framebuffer transposition was done instead — that path led to "only half is displayed", costing two more rounds.

## 4. Fix

### 4.1 The landscape desktop switches back to canvas rotation (`lv_pages/launcher_page.c`)

```c
s_cover_canvas = lv_obj_create(s_launcher_root);
lv_obj_set_size(s_cover_canvas, 1280, 720);
lv_obj_center(s_cover_canvas);
lv_obj_set_style_transform_pivot_x(s_cover_canvas, lv_pct(50), 0);   /* ★ 必须 */
lv_obj_set_style_transform_pivot_y(s_cover_canvas, lv_pct(50), 0);   /* ★ 必须 */
lv_obj_set_style_transform_rotation(s_cover_canvas, 900, 0);
```

- The cards/status bar/title are all built inside this canvas, with coordinates using the **unrotated logical coordinates**;
- enter/exit = create/delete the canvas, no longer touching the display resolution and flush.

### 4.2 The coordinate system and directions after rotation (confirmed by measurement this round)

After the canvas rotates 90°: **physical (px, py) = (720 - ly, lx)**, so

- **visual x ≡ logical x** ⇒ when the cards are arranged along logical x, **the direction keys need no conversion at all**,
  `app_runtime_set_ui_rotation(0)` (previously setting 1 as for the FC page would reverse the left/right keys).
- **visual y = 720 - logical y** ⇒ "visually up" = small logical y. The places that need to change accordingly:
  | Element | Visual expectation | Logical approach |
  |---|---|---|
  | Card title | below the card | stick to the cell **top** (`LV_ALIGN_TOP_MID, 0, 0`) |
  | Glass reflection strip | top of the card | stick to the box **bottom** (`LV_ALIGN_BOTTOM_MID, 0, -(10+k*22)`) |
  | Shadow | downward | `shadow_ofs_y` takes a **negative** value |
  | Root container gradient "dark on top, light on bottom" | vertical | `LV_GRAD_DIR_HOR` |

### 4.3 Roll back fb_rotate (`main.c`)

- Restore the native `fb_flush_cb` (including the R/B byte swap) — the fb_rotate version **missed the R/B swap**, so even if the picture appeared the colors would be reversed;
- remove `fbr_init` / `fbr_map_pointer` / the display resolution switch;
- delete `lv_hardware/fb_rotate.c` / `.h` (the Makefile uses `wildcard`, so deleting the files removes them completely).

### 4.4 The back key (item 4 of the user's 7 pieces of feedback)

No longer relying on `fbr_request_exit`, changed to the launcher providing externally:

```c
/* lv_pages/launcher_page.h */
bool launcher_cover_active(void);
void launcher_cover_close(void);
```

Both ESC paths in `main.c` (physical key / USB keyboard) are changed to
`if(launcher_cover_active()) { launcher_cover_close(); return; }`
⇒ pressing the "pay-bill" (买单) key on the landscape desktop first returns to the portrait desktop, instead of exiting the desktop.

## 5. Verification

- Enter landscape and capture a frame (`ssh_tools/grab_screen.py`): **100% of the screen non-black**, no longer white screen/half screen;
  the picture contains 3 cards (left/enlarged middle/right), and the four status bar elements (time, WiFi, Bluetooth, battery).
- After correcting the decoration directions, capture another frame: the reflection strip at the top of the card, the title below the card, icons centered, shadow downward.
- **Regression**: delete the temporary self-check switch and restart → the portrait desktop's 20 icons + status bar are all normal; the landscape changes did not break the original desktop.
- Long-term observation on the device: the process is alive, no segfault, log `[cover] landscape on, items=N canvas=1280x720 rot=900`.

## 6. Lessons (anti-pattern record)

1. **★ Before characterizing "device/platform does not support X", first search for a successful use case of X in this project.**
   ```sh
   grep -rn "transform_rotation\|transform_scale" --include=*.c lv_pages/
   ```
   If there is a precedent → diff item by item (size / parent container / pivot / draw order / state), and the difference is the root cause.
   **One failure ≠ the capability does not exist**; escalating a failure to a characterization = covering a small mistake with a bigger one.
2. **★ Comments must be read by scope**. `/* transform disabled */` written in `launcher_start_zoom()`,
   means "this press-zoom animation is turned off", **not** "transform is unavailable on the whole machine".
   02 treated it as evidence of the latter, and the direction was reversed.
3. **The user's pointer is often the shortest path**. The user said "implement it with reference to the FC game page source",
   which is equivalent to "there is a ready-made correct implementation in the repository" — the source should be read first thing, instead of starting a separate set.
4. **Changing the implementation means colors must be re-verified**. The fb_rotate version missed the R/B swap, showing that when "rewriting the flush path" one must
   compare item by item against the original implementation (byte order, stride, page flipping).
5. **After overturning an old conclusion, the archived documents and Skills must be corrected**, otherwise the wrong conclusion will pollute the next judgment
   (this round has synchronized corrections to `ref_LVGL_页面框架.md` and the `gui-render-blank-diagnosis` Skill).

## 7. Leftovers

- The landscape card sizes (unselected 300, selected ~492 logical pixels) and status bar positions are already usable; the icons are still limited by
  **the maximum font size `lv_font_montserrat_48`**, so "bigger icons" requires making another large font glyph or image-type icons.
- The USB mouse coordinates in landscape are not mapped (currently sampled with the portrait origin); the desktop mainly uses physical four-key navigation, so this does not matter for now.
- The debug entry `touch /tmp/cover_auto` followed by restarting the app enters landscape directly (marked with a TEMP comment in the source), facilitating future self-tests.
