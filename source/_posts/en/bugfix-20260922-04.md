# bugfix_20260922_04 — The desktop "FM Radio" icon renders as an empty box

> **Related commit**: 221fa7d

## Symptoms
After adding the "Radio" app entry to the desktop, the icon position, background color (warm brick red `0xe6614f`), and the text "收音机" are all correct, but **the icon itself is an empty box (tofu)**, not any meaningful graphic.

## Scope of impact
- Only the icon of the desktop "Radio" entry is affected.
- All other existing app icons are normal (they all use glyphs that actually exist in the font).
- The internal function and layout of the radio page are not affected.

## Root cause
The icon code point selected for FM in `launcher_page.c` **has no corresponding glyph at all** in `lv_font_cn_16`:

```c
#define RADIO_SYMBOL "\uF519"      /* FontAwesome broadcast-tower */
```

During LVGL rendering, `lv_font_get_glyph_dsc()` returns not-found, so a box is drawn.
`U+F519` is an icon introduced only in FontAwesome **5.x**, whereas the machine's Chinese font `lv_font/font_cn.c` (`lv_font_cn_16`) covers only the **old FontAwesome 4.x subset**.

## Diagnosis process
1. Project specification §3.4 explicitly requires: **icon availability must be verified by checking that the glyph exists; it must not be inferred from "code point range coverage" or "it looks like it"**. In the desktop screenshot, `U+F519` is a box, consistent with the specification's warning.
2. The first probe version, `glyph_probe.c`, used only the code point table from **my memory**, and as a result **the label mapping was wrong** (treating `0xF050` as `LV_SYMBOL_PREV` and `0xF0C9` as `LV_SYMBOL_LIST`).
   → **Lesson: do not use a manually mapped code point table to look up glyphs.**
3. Rewrite `glyph_probe2.c`: **use the `LV_SYMBOL_*` macros themselves as input**, decode the first UTF-8 character to obtain the code point, and completely eliminate manual mapping errors. Of the measured 52 items, **46 have glyphs and 6 are missing**, the missing ones being exactly `F519 / F2CE / F7C0 / F8CE / F130 / F09E`.
4. Then write `glyph_sweep.c` to sweep the entire range `U+F000..U+F8FF`, yielding the **authoritative list: 60 icons in total**.
   **None of them has a "radio station / antenna / radio wave" shape** — so the problem cannot be solved by "switching to a more similar-looking code point".
5. Pitfalls encountered when compiling `glyph_probe*`: `lv_font_cn_16` is defined in the application source `lv_font/font_cn.c` (it is not part of `liblvgl.a`), and the static library `liblvgl_thorvg.a` contains C++ object files → **you must link with `g++` and directly include the app's already-built `build/lv_font/font_cn.o`**:
   ```
   g++ -O1 -o glyph_probe glyph_probe.c /home/lvgl_demo/lvgl_demo/build/lv_font/font_cn.o \
       -I/home/lvgl_demo/lvgl_demo -I/root/lvgl_install/include \
       -L/root/lvgl_install/lib -llvgl -llvgl_thorvg -lpthread -lm -ldl
   ```
   (Using `gcc` reports `undefined reference to lv_font_cn_16` along with a bunch of undefined `std::` symbols.)

## Solution
From the 60 icons measured to have glyphs, choose **`LV_SYMBOL_VOLUME_MAX` (`U+F028`, a speaker with sound waves, 18x16)**, whose semantics best match "a broadcast device that can only play sound" and which is not occupied by any existing application:

```c
/* remote_src/launcher_page_patched.c */
/* 收音机图标：lv_font_cn_16 只含 60 个 FontAwesome 4.x 老图标，
 * 电台/天线/电波类（U+F519/F2CE/F7C0/F8CE/F09E/F130）全部无字形 → 会渲染成方框。
 * 实测有字形且语义最贴合"只能听声音的广播设备"的是喇叭 LV_SYMBOL_VOLUME_MAX (U+F028)。
 * 依据：设备端 glyph_sweep 全区间扫描（ssh_tools/glyph_sweep.c），不得凭记忆改。 */
#define RADIO_SYMBOL             LV_SYMBOL_VOLUME_MAX
```
(At the same time, the icon usage of the existing 16 applications was checked to avoid collisions: DIRECTORY/EDIT/AUDIO/VIDEO/KEYBOARD/SETTINGS/WIFI/BLUETOOTH/IMAGE/LIST/HOME/REFRESH/POWER/TINT/FILE are all already occupied.)

## Verification
- After recompiling, deploying, and taking a desktop screenshot: **a complete speaker graphic appears at the "Radio" icon position** (confirmed by human eyes on the physical screen), no longer a box; the focus frame also lands correctly on that cell.
- Archived image: `shots/radio_icon_fix_rgb.png` (correct byte order).

## Lessons learned
1. **Icon availability can only be verified empirically via `lv_font_get_glyph_dsc()`; it cannot be inferred from a code point table or "FontAwesome range coverage".**
   This project has already stepped on this once (`U+F519`) and once had a probe self-inflicted mishap (wrong manual code point mapping).
2. **When writing a probe, use the "authoritative source" itself as input** (here, the `LV_SYMBOL_*` macros), rather than transcribing a mapping table yourself — transcription errors make the probe itself lose credibility.
3. **First confirm "whether a solution exists at all" before acting**: only after sweeping the entire range did we learn that this font has no radio shape at all; otherwise we would have kept wasting time on "which code point to switch to".
4. To compile small probes in this project, you need to reuse **the app's already-built `font_cn.o` plus `g++`**; do not try to recompile the 27MB `font_cn.c`, and do not expect `liblvgl.a` to contain a CJK font.
