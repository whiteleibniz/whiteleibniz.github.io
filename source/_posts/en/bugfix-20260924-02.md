# bugfix_20260924_02 — "Switch desktop" landscape menu white screen freeze (the transform rendering path is unavailable)
> Related commit: 2341fad

> ⚠️ **This article's conclusion has been overturned by bugfix_20260924_03**: transform has always been available on this machine (`fc_game_page.c` uses the exact same approach);
> the real cause of the white screen is **`transform_pivot` not being explicitly set to 50%** (the default is the object's top-left corner → the 1280x720 canvas rotates around its top-left corner and moves entirely out of the visible area).
> Please defer to 03; this article is kept only as a process record of "one wrong characterization".

- Date: 2026-09-24
- Scope of impact: `lv_pages/launcher_page.c` (new feature "switch desktop" → landscape zoom menu)
- One-sentence conclusion: **in this LVGL build the `transform` (rotation/scaling) rendering path is unavailable — any object with transform is not drawn at all**;
  after switching to a pure `set_size` animation, the feature works normally.

---

## 1. Symptom and requirement

User feedback: after tapping "switch desktop" on the desktop, the screen **freezes white**.

Read-only on-site forensics (`ssh_tools/_tmp/dbg_white.sh`):

| Check item | Result |
|---|---|
| Process | `lvgl_demo` alive, PPID=1, STAT=S |
| CPU | 0% (`top` shows the process idle) |
| Log tail | lots of `[HW Key] code=115/116` and `[nav] key=19/20/27`, **no segfault / assert / fatal** |
| Conclusion | not a crash, not an infinite loop — it is **the UI not being drawn** (a rendering-layer problem) |

## 2. Localization: first rescue the device, then narrow the variables with "minimal experiments"

1. **Roll back first**: restore `lv_pages/launcher_page.c.bak_cover` → `make -j2` → atomic replacement → restart.
   The log immediately shows `[fb] flush ... px0=ffdff3ff/ffe0f3ff` (the desktop gradient background color), and the device is usable again.
2. **Then run a minimal experiment**: temporarily insert `launcher_set_cover(true)` at the end of `onCreate` (auto-enter the menu),
   so the issue can be reproduced reliably without depending on key presses, and use `grab_screen.py` to capture frames and judge layer by layer "who is not being drawn".

The progressive conclusions from three frame captures:

| Version | Frame capture result | Inference |
|---|---|---|
| Plan A: container `1280x720` + `transform_rotation=900` | only the parent container's background color remains on the whole screen, **the container and the cards are all gone** | the large container's rotation is discarded entirely |
| Plan B first version: the container is not rotated, **the cards still use `transform_scale`** | the container background + the top hint text **are drawn normally**, **all cards disappear** | transform is unrelated to object size; **anything with transform is not drawn** |
| Plan B corrected version: **zero transform**, switch to `set_size` animation | the cards, icons, and Chinese titles are all normal | root cause confirmed |

> Key comparison: in the same container, "the hint label without transform" is drawable while "the cards with transform" are not —
> the variable has been narrowed to transform alone.

## 3. Root cause

**The transform rendering path in this LVGL build (`/root/lvgl_install` precompiled liblvgl.a) is unavailable at runtime.**

- Earlier I judged "supported" with the static symbol method: in `nm liblvgl.a`, `lv_draw_sw_transform` is in the **T section**, and `lv_obj_set_style_transform_rotation / scale_x / scale_y` are all present → conclusion "it links, it should draw".
  **This judgment only proves the symbols exist, not that it runs correctly.**
- The strongest corroborating evidence was in the source all along: the beginning of `launcher_page.c`'s `launcher_start_zoom()` is
  `(void)target; return; /* transform disabled */`. `git log -S` shows it **came with the v1.0 initial commit** —
  it was interpreted at the time as "the upstream disabled the press-zoom effect itself", **but its actual meaning is "transform cannot be drawn on this machine, so it is turned off"**.
  The "disabled" in the comment is **evidence**, not noise.

## 4. Fix

`lv_pages/launcher_page.c` (patch scripts `ssh_tools/_tmp/patch_cover3.py` + `patch_cover4.py` + `patch_cover5.py`):

1. **Abandon the full-screen rotation plan** (switch to a horizontally zoomed strip within the portrait screen): the screen is 720×1280, cards are arranged horizontally,
   with the selected item at 1.5× and the left/right neighbors at 1.0×; parameters `CARD=200 / GAP=250 / SEL=384 / SIDE=256`,
   which exactly fills the 720 width as `200 + 250 + 250 = 700` with no overlap.
2. **`cover_geom()` completely drops transform**, switching to a size animation:
   ```c
   lv_obj_set_size(it->cell, w, h);
   lv_obj_set_pos(it->cell, cx - w / 2, s_cover_cy - h / 2);
   lv_obj_set_size(it->box, bw, bw);        /* 色块跟着放大 */
   lv_obj_align(it->box, LV_ALIGN_TOP_MID, 0, 0);
   lv_obj_set_width(it->title, w);
   lv_obj_align(it->title, LV_ALIGN_TOP_MID, 0, bw + 6);
   ```
   `cover_anim_cb` still uses a single `lv_anim` to interpolate all cards' `cx` and `scale` uniformly (320ms, ease_out).
3. Delete the now-useless `transform_pivot_*` on the cells.
4. When entering the menu, **add one "hide the root's other child objects"** (`ch2 != s_cover_root`):
   the grid is created by tileview in the later part of `onCreate`, so hiding it only once on entry is not stable enough.

## 5. Verification

- Three consecutive frame captures (`outputs/cover_check4~6.png`): the container background, top hint, the enlarged middle card, the two normal side cards,
  the white icons, and the Chinese titles (任务管理 / 切换桌面 / 相机) are **all normal**.
- Left/right key navigation: after `[cover] built n=19 cx=360 cy=576`, pressing the right key 11 times, the selected item centers and enlarges one by one as expected (screenshot `cover_check5.png`).
- After deploying the final version (with the temporary auto-entry removed), the desktop gradient background color is normal, with no crash.

## 6. Lessons (anti-pattern record)

1. **"The symbol exists ≠ the capability is available"**: `nm` can only prove it links. When it comes to rendering/driver capabilities, **you must capture an actual frame**,
   or run an experiment on a minimal object — do not treat static symbols as the end of capability verification.
2. **Upstream comments must be read as evidence**: if `/* transform disabled */` had been taken seriously earlier, a whole round of white-screen incident would have been saved.
   When you encounter "disabled / not supported / FIXME", first ask "why did they turn it off".
3. **Troubleshooting must do subtraction on the variables**: this round relied on "temporary auto-entry + frame captures" to narrow the four lines of
   "key path / focus group / layout / rendering" down to the single line of "transform present vs absent", which pinned down the root cause.
4. **Roll back failures first**: once there are many changes, the first action is to restore to a usable baseline (source files `.bak_*` + atomic replacement),
   then experiment under safe conditions, avoiding leaving the user facing a broken picture for a long time.
5. **USB key injection cannot verify the physical key path**: `/root/vhwkey2` goes through `usb_map`, which has different semantics from physical keys;
   the actual feel of Enter/ESC must be verified by a human (see §7 for details).

## 7. Leftovers

- After entering the menu, pressing the **physical 福利 (welfare) key (Enter) should return** after selecting "switch desktop", and pressing the **physical 买单 (pay-bill) key (ESC) should return** —
  these two are to be confirmed by the user on the device (the USB-injected ENTER/ESC did not produce the expected effect in this round's testing, but the injection semantics differ from physical keys,
  so no conclusion can be drawn from it).
- The card enlargement only covers the color block and the overall size; **the icon glyph font size does not scale** (there is no larger icon font, only `montserrat_24`);
  if "the icons should get bigger too", another large font size needs to be introduced.
- Each entry into the menu prints one line `[cover] built n=.. cx=.. cy=..` (for diagnostics, kept for future troubleshooting).
