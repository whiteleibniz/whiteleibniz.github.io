# bugfix_20260923_15 — GBA exit "intermittently hangs on the game picture" (the 买单 key leaked to the UI layer → this page was popped → nobody repainted)

- Date: 2026-09-23
- Symptom: pressing the 买单 ("pay-the-bill") key to exit a GBA game, the miniretro process does exit, but sometimes the picture does not refresh and stays on the game picture; sometimes it returns to the game list normally. A probabilistic failure.
- Files touched: `lv_pages/gba_game_page.c` (exit flow), `extern/miniretro/miniretro_gba.c` (`fb_restore()`)
- One-sentence conclusion: **three coordinated defects** — during exit the key thread is occupied by `sleep` → the residual key event leaks to the UI layer → this page is treated as "back" and popped → the timer responsible for the full-screen repaint disappears with the page → the screen stays on the game picture.

## 1. Background: this round and the previous version (bugfix_14) are not the same problem

bugfix_14 fixed "on frontend exit the foreground page stops on page 1 while the UI layer only draws page 0 → the screen freezes". That version added dual-layer fallback page flipping in parent and child, and **the page flip itself is already reliable** (the log shows `fb pan 回第0页(无条件)`).

The key difference this round: **the process really did exit and the page really was flipped back to page 0 (measured `yoffset=0`), but the screen content is still the game picture**. In other words, the problem has moved from "the page flip" to "**who paints the new UI on**".

## 2. Root cause (three coordinated points; missing any one it does not hold)

### 2.1 The 买单 key leaked to the UI layer, "backing" this page away with it

The old `gba_exit_to_list()` did `usleep(600ms)` in the **key thread** to wait for the supplementary SIGKILL, so:

1. During those 600ms nobody read `/dev/input/event0`, and input events piled up in the kernel buffer;
2. The frontend exited about **30ms** in, the kernel reclaimed the evdev fd in about **450ms**, and the wait thread then removed the key interceptor;
3. When the key thread woke up the interceptor **was already gone** → the piled-up "买单 release" events flooded into the UI layer all at once;
4. It was treated as the "back" key (ESC) → this page was popped.

### 2.2 Once the page is destroyed, the timer responsible for the full-screen repaint is gone too

`gba_timer_cb` is attached to **this page** (`lv_timer_create`), and `lv_timer_del` deletes it when the page is destroyed. So the "full-screen repaint" **depends on the page surviving** — once 2.1 happens, nobody calls `lv_obj_invalidate` + `lv_refr_now` anymore.

### 2.3 The frontend wrote the game picture into the UI layer's territory

The old `fb_restore()`, after flipping back to page 0, also memcpy'd the foreground page to page 0 in full ("freeze the last frame"). Page 0 is exactly the page the UI layer always draws on → once nobody repaints, what remains on the screen is the game picture. This is the **material form** of this failure.

## 3. Evidence (device log)

```
[gba] 买单键 -> 退出游戏并返回列表        ← 拦截器命中, 开始退游戏
[miniretro][timing] 主循环退出 t=0.1 ms
[miniretro][timing]   fb pan 回第0页(无条件) t=0.3 ms
[miniretro][timing]   fb 定格最后一帧(不清屏) t=14.5 ms
[nav] key=27                              ← 同一个买单键又漏给了 UI 层
[pm] 页面 'gba_game' 离场，摘掉 7 个焦点组残留控件（现共 19）
```

- `[nav] key=27` (27 = LV_KEY_ESC = 买单) proves **the 买单 key really did leak to the UI layer**;
- The immediately following `[pm] 页面 'gba_game' 离场` proves **this page was popped**;
- Another exit in the same log has no `[nav] key=27` → this is exactly the source of "sometimes good, sometimes bad";
- The failure site measured `yoffset=0` (the page has returned home) → ruling out the bugfix_14 type of "the page did not flip back", locking onto "nobody repaints".

## 4. Fix (8 changes)

### 4.1 The key thread returns immediately; the supplementary kill is handed to the wait thread

`gba_exit_to_list()` only sends `SIGTERM` and then returns — the key thread must go back to reading the keyboard right away and swallow the residual events produced during the exit (while the interceptor is still in place).

### 4.2 The full-screen repaint switches to `lv_async_call`, no longer depending on the page surviving

New `gba_repaint_async()`, queued by `lv_async_call` for the main thread:

```c
static void gba_repaint_async(void *unused)
{
    (void)unused;
    lv_obj_invalidate(lv_screen_active());
    lv_refr_now(NULL);
}
```

The `lv_async_call` callback is not attached to any page object, so **it executes whether or not the page exists**; at this moment `lv_screen_active()` is already the page that should be displayed, and a full-screen repaint covers the residue.

### 4.3 Corpse reaping switches to non-blocking polling (incidentally moving UI restoration about 570ms earlier)

The wait thread first polls with `waitpid(WNOHANG)` for up to 600ms, and **only sends the supplementary SIGKILL if the timeout expires without death**, then blocks for reaping. The criterion is still a single hard event — **the child process really disappears**; the moment of timeout is not "treat it as exited" but forcing it to die. Never set an upper limit of "running for N seconds counts as exit".

### 4.4 The frontend drops the full-page memcpy

Under double buffering page 0 holds the game's previous frame anyway, visually indistinguishable from "the last frame"; dropping it both saves the 3.7MB / ~15ms copy and removes the race source of "writing external content into the UI layer's territory".

### 4.5 The page destruction path gets the same fallback

Returning to the desktop via the "back" button in the top-right corner goes through `gba_on_destroy`, which also gets one more `lv_async_call` repaint.

### 4.6 `gba_on_destroy` sends SIGTERM first, then SIGKILL

The original implementation sent SIGKILL directly, which would break the .sav save write in half on the SD card; changed to wait at most 300ms before the supplementary kill.

### 4.7 The interceptor removal is moved later in the order

`hardware_keys_set_interceptor(NULL, NULL)` is moved to the very end of the recovery section, letting the key thread swallow the residual events first as much as possible.

### 4.8 `gba_timer_cb` validates the object before focusing

Add `lv_obj_is_valid` before `lv_group_focus_obj(s_gba.btns[0])`.

## 5. Verification

- Frontend `sh build.sh` → `FRONT_RC=0`; main program `make -j2` → `MAKE_RC=0` / 0 error
- Atomic replacement `BIN_OK`, single instance after restart; `build/lvgl_demo` and `/usr/local/bin/lvgl_demo` have the same size and timestamp
- Source verification: `gba_repaint_async` 5 hits, `lv_async_call` 4 hits, the old `usleep(600...)` calls are gone (only explanatory comments remain)
- Pending on-device retest: consecutive "enter game → 买单 exit" runs, each should return to the game list with the picture refreshing immediately

## 6. Anti-pattern record

1. **Letting "UI restoration" depend on the survival of a certain page object (timer/control)** — once the page is destroyed first, the restoration silently fails with no error at all.
2. **`sleep`ing in your own thread to wait for the supplementary kill** — while blocked nobody consumes input, and the residual events flood into the UI layer together after the interceptor is removed.
3. **Writing content "into someone else's page"** (copying a frame into the page the UI layer always draws on) — as long as the other party's repaint timing deviates even slightly, the residue stays on the screen permanently.

## 7. Leftovers

- .sav flushing: this round added a wait window of at most 300ms to `on_destroy`, but no save integrity verification was done.
- The FC side is unaffected (independent frontend + independent page) and was not changed this round.
