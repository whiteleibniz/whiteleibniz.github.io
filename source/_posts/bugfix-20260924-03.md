# bugfix_20260924_03 — 「切换桌面」横屏只显示一半（根因是 pivot 未设，不是 transform 不可用）
> 关联提交：2341fad

- 日期：2026-09-24
- 影响范围：`lv_pages/launcher_page.c`（横屏桌面）、`main.c`（回滚）、`lv_pages/launcher_page.h`
- **本文同时推翻** `bugfix_20260924_02` 的结论。
- 结论一句话：**transform 在这台设备上一直是可用的**；02 的白屏根因是
  **`transform_pivot` 没设**（默认是对象左上角，1300x720 画布绕左上角转 90° 后整个转出可视区）。
  横屏正确做法 = 与 `lv_pages/fc_game_page.c` 完全同款：1280x720 逻辑画布 + `lv_obj_center` +
  `transform_pivot=50%` + `transform_rotation=900`。

---

## 1. 现象与诉求

- 02 之后横屏改用「flush 层整屏转置」（`lv_hardware/fb_rotate.c` + 运行时改显示分辨率）。
- 用户反馈：**"桌面只显示一半"**，并要求 **"参照 FC 游戏 page 源码实现横屏显示"**。

用户的提示本身就是正确答案：`fc_game_page.c` 是**同项目里长期在用的横屏页面**，
它用的正是 `transform_rotation`。

## 2. 定位：为什么 02 会得出"transform 不可用"

把两次实现放到一起 diff，差异只有一行：

| | 02 的失败版本 | `fc_game_page.c`（一直正常） |
|---|---|---|
| 逻辑画布 | 1280x720 | 1280x720 |
| `lv_obj_center(canvas)` | 有 | 有 |
| **`transform_pivot_x/y = lv_pct(50)`** | **没有** | **有** |
| `transform_rotation` | 900 | 900 |
| 父容器 | 页面 root | 页面 root |

`fc_game_page.c` 的注释里早就把答案写着：

> 旋转支点必须显式设成中心！这台 LVGL style 默认的 `transform_pivot` 是对象左上角，
> 不设的话画布会绕左上角转出屏幕外，**整页一个像素都看不到**。

**"整页一个像素都看不到" = 02 观察到的白屏**。根因一直都在注释里。

## 3. 根因

1. **直接原因**：`transform_pivot` 未设 → 默认 pivot = 对象左上角。1280x720 画布绕左上角转 90° 后，
   可视区域落在屏幕外 → 看起来"容器和卡片全部不见"。
2. **02 的误判链**：
   - 观察到"带 transform 的对象不绘制"（现象正确）；
   - 但把它**上升为设备级定性**"这台设备的 transform 渲染路径不可用"（结论错误）；
   - 反例就在同一个仓库里（`fc_game_page.c`），**当时没有去搜**。
   - 于是弃用了正确方案，改做整屏 framebuffer 转置 —— 那条路又引出"只显示一半"，多花两轮。

## 4. 修复

### 4.1 横屏桌面改回画布旋转（`lv_pages/launcher_page.c`）

```c
s_cover_canvas = lv_obj_create(s_launcher_root);
lv_obj_set_size(s_cover_canvas, 1280, 720);
lv_obj_center(s_cover_canvas);
lv_obj_set_style_transform_pivot_x(s_cover_canvas, lv_pct(50), 0);   /* ★ 必须 */
lv_obj_set_style_transform_pivot_y(s_cover_canvas, lv_pct(50), 0);   /* ★ 必须 */
lv_obj_set_style_transform_rotation(s_cover_canvas, 900, 0);
```
- 卡片/状态栏/标题全部建在这块画布内，坐标用**未旋转的逻辑坐标**；
- 进入/退出 = 建/删画布，不再碰显示分辨率与 flush。

### 4.2 旋转后的坐标系与方向（本次实测确认）

画布转 90° 后：**物理 (px, py) = (720 - ly, lx)**，所以

- **视觉 x ≡ 逻辑 x** ⇒ 卡片沿逻辑 x 排列时，**方向键不需要任何换算**，
  `app_runtime_set_ui_rotation(0)`（原按 FC 页设 1 会让左右键反向）。
- **视觉 y = 720 - 逻辑 y** ⇒ 「视觉上方」= 逻辑 y 小。需要跟着改的地方：
  | 元素 | 视觉期望 | 逻辑做法 |
  |---|---|---|
  | 卡片标题 | 卡片下方 | 贴 cell **顶部**（`LV_ALIGN_TOP_MID, 0, 0`） |
  | 玻璃反光条 | 卡片顶部 | 贴 box **底部**（`LV_ALIGN_BOTTOM_MID, 0, -(10+k*22)`） |
  | 阴影 | 向下 | `shadow_ofs_y` 取**负** |
  | 根容器渐变"上深下浅" | 垂直 | `LV_GRAD_DIR_HOR` |

### 4.3 回滚 fb_rotate（`main.c`）

- 恢复原生 `fb_flush_cb`（含 R/B 字节交换）——fb_rotate 版本**漏了 R/B 交换**，即使画面出来颜色也会反；
- 移除 `fbr_init` / `fbr_map_pointer` / 显示分辨率切换；
- 删除 `lv_hardware/fb_rotate.c` / `.h`（Makefile 用 `wildcard`，删文件即彻底摘除）。

### 4.4 返回键（用户 7 条反馈中的第 4 条）

不再依赖 `fbr_request_exit`，改为 launcher 对外提供：

```c
/* lv_pages/launcher_page.h */
bool launcher_cover_active(void);
void launcher_cover_close(void);
```
`main.c` 的两条 ESC 路径（物理键 / USB 键盘）都改成
`if(launcher_cover_active()) { launcher_cover_close(); return; }`
⇒ 横屏桌面按「买单」键先退回竖屏桌面，而不是退出桌面。

## 5. 验证

- 进入横屏抓帧（`ssh_tools/grab_screen.py`）：**全屏非黑 100%**，不再是白屏/半屏；
  画面含 3 张卡片（左/中放大/右）、状态栏四要素（时间、WiFi、蓝牙、电量）。
- 修正装饰方向后再抓帧：反光条到卡片顶部、标题到卡片下方、图标居中、阴影向下。
- **回归**：删掉临时自验开关重启 → 竖屏桌面 20 个图标 + 状态栏全部正常，横屏改动没有破坏原桌面。
- 设备端长期观察：进程存活、无 segfault、日志 `[cover] landscape on, items=N canvas=1280x720 rot=900`。

## 6. 经验（反模式记录）

1. **★ 下"设备/平台不支持 X"的定性前，先在本项目里搜 X 的成功用例。**
   ```sh
   grep -rn "transform_rotation\|transform_scale" --include=*.c lv_pages/
   ```
   有先例 → 逐项 diff（尺寸 / 父容器 / pivot / 绘制顺序 / 状态），差异点即根因。
   **一次失败 ≠ 能力不存在**；把失败上升为定性 = 用一个更大的错误掩盖小错误。
2. **★ 注释要按作用域读**。`/* transform disabled */` 写在 `launcher_start_zoom()` 里，
   意思是"这个按下缩放动画被关掉"，**不是**"整机 transform 不可用"。
   02 把它当成了后者的证据，方向就反了。
3. **用户的指向往往是最短路径**。用户说"参照 FC 游戏 page 源码实现"，
   等价于"仓库里有现成正确实现" —— 应当第一时间去读那份源码，而不是自己另起一套。
4. **换了实现就要重新验颜色**。fb_rotate 版漏掉 R/B 交换，说明"重写 flush 路径"时必须
   逐项对照原实现（字节序、stride、页翻转）。
5. **推翻旧结论后必须回改已归档的文档与 Skill**，否则错误结论会污染下一次判断
   （本次已同步修正 `ref_LVGL_页面框架.md` 与 `gui-render-blank-diagnosis` Skill）。

## 7. 遗留

- 横屏卡片尺寸（未选中 300、选中 ~492 逻辑像素）与状态栏位置已可用；图标仍受限于
  **最大字号 `lv_font_montserrat_48`**，"图标更大"需另做大字号字形或图片型图标。
- 横屏下的 USB 鼠标坐标未做映射（当前按竖屏原点采样）；桌面以物理四键导航为主，暂不影响。
- 调试入口 `touch /tmp/cover_auto` 后重启应用可直接进横屏（源码中带 TEMP 注释），便于后续自测。
