# 展讯 SC9832A（spd-box）FM 收音机 —— LVGL 界面设计与交互规格

> **读者对象**：实现收音机 App 的工程师 / AI 助手
> **使用方式**：先读 §1–§2 拿到屏幕与硬件约束 → 按 §3 排图标 → 按 §4 画页面 → 按 §5 拆功能优先级
> **核心价值**：所有尺寸按本机实测参数（720×1280 竖屏、`lv_font_cn_16` 行高 31px）算出，避免画完再改行高；所有功能项均标注了对应的驱动 ioctl，避免设计出实现不了的交互

---

## 1. 设计约束（先定死，再画页面）

### 1.1 屏幕与字体硬参数

| 项目 | 值 | 来源 / 影响 |
|---|---|---|
| 分辨率 | **720 × 1280**（竖屏） | Framebuffer 实测；所有坐标基于此 |
| LVGL 版本 | 9.6.0 | 用 `lv_obj_set_style_transform_rotation` 等 9.x API |
| 默认中文字体 | `lv_font_cn_16` | **禁止**用 `LV_FONT_DEFAULT`（Montserrat-14 无 CJK，会出方格豆腐块） |
| `lv_font_cn_16` metrics | **line_height = 31px，base_line = 9px** | **关键**：名义 16px 字号，实际占 31px 行高。按 16px 估算的布局必然裁切中文 |
| 图标字库 | FontAwesome 码位覆盖区间 **61441 ~ 63650**（0xF001–0xF8A2） | 选图标时必须落在该区间内 |
| 物理按键 | 点餐=114(LEFT)、服务=102(RIGHT)、福利=115(ENTER)、买单=116(BACK) | 导航/返回走按键，无触摸屏时要能盲操作 |

> ⚠️ **本项目历史教训**：已有过因为按旧字体硬编码行高（36/60px）导致中文被裁切的返工。
> 本规格内所有 y 坐标均已按 **31px 网格**重算，实现时不要"视觉微调"成 16px 网格。

### 1.2 硬件能力边界（决定 UI 能显示什么）

以下能力已由驱动符号**实测确认**（见 `FM收音打通_AI指导手册.md` §2），UI 设计据此取舍：

| 驱动能力 | 对应 UI 元素 | 备注 |
|---|---|---|
| `TUNE` / `TUNE_NEW` | 手动调谐、列表跳转频点 | 直接定频，响应快 |
| `SEEK` / `SEEK_NEW` | ◀◀ / ▶▶ 搜台 | 找**下一个强信号**，非逐频步进 |
| `SCAN` / `SCAN_NEW` / `STOP_SCAN` / `SCAN_GETRSSI` | 自动全频扫描 + 进度条 + **可中断** | 四个命令成套：`SCAN` 发起全扫、`SCAN_GETRSSI` 逐点取场强以驱动进度与去噪、`STOP_SCAN` 中途取消 |
| `GETRSSI` | 信号强度指示条 | 单频点实时查询 |
| `MUTE` / `SETVOL` / `GETVOL` | 静音开关、音量滑条 | 注意：**仍有 `SETVOL`，但主输出音量可能另走 ALSA**，见 §5 仲裁表 |
| `RDS_SUPPORT` / `RDS_ONOFF` | RDS 开关（上层关上层开） | 建议常开 |
| `rds_get_ps()` | **电台名 PS（8 字符）** → 主频点下的台名 | RDS 最有价值的字段 |
| `rds_get_rt()` | **电台文本 RT（64 字符）** → 滚动字幕 | 用于 second line 滚动 |
| `rds_get_pty()` | 节目类型（新闻/音乐/交通…） | 可显示为小标签 |
| `rds_get_af()` | 备用频率 AF → **可自动切到信号更好的同套节目频率** | 高价值增弎项，非 P0 |
| `rds_get_ct()` | 电台时钟 | 可作为状态栏时间的可选来源 |
| `rds_get_ews()` | 紧急广播 | 有合规意义，建议预留提示位 |
| `GETMONOSTERO` / `SETMONOSTERO` | 立体声 ST 指示灯 | 单双声道指示 |
| `OVER_BT_ENABLE` | **FM 音频改走蓝牙** | §5.4 声道仲裁的核心开关 |
| `ANA_SWITCH` / `I2S_SETTING` / `GET_I2S_INFO` | 模拟 cntl vs I2S 两路音频路径选择 | 实现一个即可，见 §5.4 |

> ⚠️ **需要实测确认（当前为待验证项，不要当成事实）**
>
> 1. **FM 是否必须播耳机作天线**。芯片侧 FM 射频输入常见做法是复用耳机线；本机 ALSA 拓扑里有独立的 FM 设备
>    （`01-04: Dfm sprd-codec-fm-4`），暗示可以不靠耳机。**必须先做完 §5.4 音频路径试验再定方案**；
>    若最终需要耳机，UI 必须在无耳机时用全屏插画提示"请插入耳机"（见 §4.1 状态 Z2）。
> 2. RDS 解析函数虽然在驱动里，但**是否已由用户态提供数据结构**尚无头文件佐证，`Struct number` 待定。
> 3. 音量 `SETVOL` 与实际主输出音量的关系：可能只是 FM 模块内部增益，主管量另在 ALSA。

## 2. 系统定位：收音机在整个 App 里的位置

```
桌面 launcher（g_launcher_page）
   ├── 状态栏：左=时间  右=电池 / WiFi / 蓝牙图标
   │
   └── 应用网格 s_apps[]（第 3 行第 2 个）
         ├── … 网络（LV_SYMBOL_WIFI,  0x56ccf2）
         ├── 蓝牙（LV_SYMBOL_BLUETOOTH, 0x1e88e5）   ← 索引 7
         ├── 收音机（新）                            ← 索引 8 ★ 紧跟蓝牙
         ├── 图库
         └── …
                 │ 点击
                 ▼
        收音机页 g_radio_page（新增）
                 │ 后台常驻播放、返回桌面不停台
                 ▼
        FM daemon（新增，/tmp/fm_ctl.sock）
                 │ ioctl / AT → /dev/fm
                 ▼
        Marlin2 芯片 FM 部件（与 WiFi/蓝牙共享 SDIO）
```

**与其他既有页面的关系**：

| 页面 | 关系 | 交互 |
|---|---|---|
| 网络页 `g_network_page` | **前置依赖** | FM 固件随 WiFi 一次下载好；WiFi 未拉起 ⇒ FM 不可用（须灰化图标或弹提示） |
| 蓝牙页 `g_bluetooth_page` | **声道互斥** | A2DP 播放时开 FM ⇒ 需上层仲裁，见 §5.4 |
| 音乐/视频页 | **声道互斥** | 本地播放与 FM 互斥 |
| 桌面 `g_launcher_page` | 返回关系 | 返回不停台，见 §5.5 |

## 3. 入口设计与图标（要求 ①）

### 3.1 桌面网格排布

当前 `s_apps[]`（`lv_pages/launcher_page.c` 第 94 行起）顺序：

| 索引 | 名称 | symbol | 背景色 |
|---|---|---|---|
| 6 | 网络 | `LV_SYMBOL_WIFI` | `0x56ccf2` |
| **7** | **蓝牙** | `LV_SYMBOL_BLUETOOTH` | `0x1e88e5` |
| **8** | **收音机（新增）** | 见 §3.2 | `0xe6614f`（建议） |
| 9（原 8） | 图库 | … | … |

> **视觉顺序由 `s_apps[]` 数组顺序决定**（网格遍历用 `sizeof(s_apps)/sizeof(s_apps[0])`，见 `launcher_page.c:985` 与 `:1055`），
> 所以只要在数组里把它放在蓝牙条目之后，就自动排到蓝牙后面。

### 3.2 三处代码改动（必改，缺一不可）

**（1）枚举** —— `launcher_page.c` 第 40 行附近的枚举：

```c
    LAUNCHER_APP_BLUETOOTH,
    LAUNCHER_APP_RADIO,             /* ★ 新增 */
    LAUNCHER_APP_GALLERY,
```

> ⚠️ **建议不要把枚举插在有隐式连续值的中间**：上面写法会让 `GALLERY` 及其后各项的数值整体 +1。
> 若担心有状态持久化了旧数值，更稳的写法是**加在枚举末尾**（`LAUNCHER_APP_EXTERN = 1000` 之前），
> 视觉顺序仍由 `s_apps[]` 数组控制。两种方式二选一，选定后全项目统一。

**（2）数组** —— `s_apps[]`：

```c
    { LAUNCHER_APP_BLUETOOTH, "蓝牙",   LV_SYMBOL_BLUETOOTH, 0x1e88e5 },
    { LAUNCHER_APP_RADIO,     "收音机", RADIO_SYMBOL,       0xe6614f },  /* ★ 新增 */
```

**（3）跳转分支** —— `open_app` 的 switch：

```c
        case LAUNCHER_APP_RADIO:
            lv_start_activity(&g_radio_page, LV_PAGE_FLAG_DEFAULT, LV_PAGE_ANIM_SLIDE_LEFT, 220);
            break;
```

标准跳转写法与其他页面一致（`lv_start_activity(&g_xxx_page, LV_PAGE_FLAG_DEFAULT, LV_PAGE_ANIM_SLIDE_LEFT, 220)`）。

### 3.3 图标选型

LVGL 内置符号里**没有收音机 dedicated 符号**。三个候选：

| 候选 | 码位 | 十进制 | 是否在已确认覆盖区间 | 评价 |
|---|---|---|---|---|
| **broadcast-tower** | `U+F519` | 62745 | ✅ 在 61441–63650 内 | **推荐首选**：塔形，识别度高 |
| podcast | `U+F2CE` | 62158 | ✅ | 备选，偏"播客"语义 |
| satellite-dish | `U+F7C0` | 63424 | ✅ | 备选，偏"卫星"语义 |
| ~~radio~~ | `U+F8CE` | 63702 | ❌ **超出 63650** | **禁止使用**，会渲染成豆腐块 |

```c
/* 建议放在 radio_page.h 或公共 symbols 头里 */
#define RADIO_SYMBOL "\uF519"   /* broadcast-tower，待 §3.4 验证后固化 */
```

**背景色**建议 `0xe6614f`（暖砖红）：桌面现有色板里蓝色系已被网络/图库/蓝牙大量占用，红色系只有关机（`0xe74c3c`）和音乐（`0xeb5757`）；暖砖红与这三者都不撞色，且暖色调符合"收音机/广播"的常规心理暗示。

### 3.4 图标验证（**交付前必做，缺此步不算完成**）

区间覆盖是间接证据，**码位是否有具体字形必须实测**：

```sh
# 方法：写个最小 LVGL 测试页渲染该码位，截图看是字形还是豆腐块
# 参考本项目既有验证思路：写已知值 → 出图 → 人眼确认
```

> ⚠️ **禁止用"渲染出来看着像"自证**：这与本项目显示类问题的排障纪律一致
> （"抓数据→按假设解码→看起来对"不是证据）。必须**人眼在物理屏上确认**是塔形图案而非方框。
>
> 若 `U+F519` 缺字形 → 退化方案：用 32×32 PNG 资源，或退而用 `LV_SYMBOL_AUDIO`（与"音乐"语义冲突，不推荐）。

### 3.5 设置页排布

设置页 `g_settings_page` 内**建议新增两项**（跟随蓝牙项之后）：

| 控件 | 作用 |
|---|---|
| 开关「收音机开机自启」 | 控制 `fm_radio.start` 是否随系统起来（默认关，见 §5.5） |
| 条目「收音地区与频段」 | 中国 87.5–108.0 MHz / 步进 100 kHz；留口给日本 76–90 MHz、欧规 50 kHz 步进 |

> 这两项属 **P2**，可在 P0/P1 完成后再补。

## 4. 页面布局（要求 ②）

### 4.1 分区总览（720 × 1280）

按 31px 行高网格排版，纵向 8 个分区：

| # | 分区 | y 范围 | 高度 | 内容 |
|---|---|---|---|---|
| A | 标题栏 | 0 – 72 | 72 | 返回按钮、标题「收音机」、耳机/声道状态小图标 |
| B | 频段模式条 | 80 – 111 | 31 | `FM` + `87.5 – 108.0 MHz` + `100 kHz` + ST 立体声标 |
| C | 当前频点 | 120 – 232 | 112 | **大字号** `97.4` + `MHz`；下方 RDS 台名 PS |
| D | 刻度尺 | 244 – 340 | 96 | 频率刻度 + **调谐指针** + 收藏频点标记 |
| E | 信号与 RDS | 352 – 413 | 61 | RSSI 五格信号条 + RT 滚动字幕 |
| F | 控制区 | 430 – 590 | 160 | ◀◀ / 搜台 / 静音 / 搜台 / ▶▶ |

### 4.2 分区详细规格

#### A. 标题栏（0–72）

| 元素 | 位置 / 尺寸 | 说明 |
|---|---|---|
| 返回按钮 | x=0, 56×56，`LV_SYMBOL_LEFT` | 点击 → 返回桌面但**不停台**（见 §5.5） |
| 标题 | 居中，`lv_font_cn_16` | 「收音机」 |
| 耳机状态 | x = 720-56 | 无耳机显示 🎧 划掉；有耳机隐藏。依赖 §1.2 待验证项 1 |
| 声道指示 | 紧邻左侧 | 小标「耳机 / 扬声器 / 蓝牙」，与 H 区联动，点击可弹声道切换窗（P2） |

#### B. 频段模式条（80–111）

单行 31px，四段信息：`[FM] [87.5 - 108.0 MHz] [100 kHz] [ST]`。
ST 立体声标仅在 `GETMONOSTERO` 返回立体声时点亮，作为 RDS 可用性的间接指示。

#### C. 当前频点（120–232）—— **视觉焦点**

| 元素 | 规格 |
|---|---|
| 频率数字 | **48px 加粗**（需引入或用现有最大字号；若 `lv_font_cn_16` 无此尺寸，用 LVGL 缩放变换或新增点阵字号） |
| 单位 `MHz` | 16px，随数字右对齐 |
| RDS 台名 | 16px 单行，取 `rds_get_ps()`，无 RDS 时显示空白或「—」 |
| 字号提醒 | 该区域高度 112px，容纳一行 48px（占 62px 行区）+ 一行 16px（31px）+ 调节余量 |

> ⚠️ 48px 中文字号**必须先用实际情况验证**（`lv_font_cn_16` 为 16px 点阵）。
> 若该字号不可用，两种替代方案：
> 一是用 LVGL 的 `lv_obj_set_style_transform_scale()` 对数字做放大（点阵字体放大后有锯齿，效果一般）；
> 二是新增一个 48px 中文/数字点阵字号（效果最好，但增加固件体积）。此项属 P1 依赖，需实测后定。

#### D. 刻度尺与调谐指针（244–340）—— **核心交互件**

- **刻度生成**：按当前频段上下界与步进（默认 87.5–108.0 MHz / 100 kHz）计算，绘制主刻度（每 1 MHz）+ 次刻度（每 0.5 MHz）。
- **指针**：倒三角，x 由当前频点线性映射；文件 `lv_obj_set_x()` 更新，切换 ANIM 200ms。
- **收藏标记**：在对应频点 x 上画 ★ 形小标记，标记位置随收藏列表实时增删。
- **交互**：
  - 拖动 / 左右划 → **频点微调**（每 move 10px ≈ 100 kHz），实时 `TUNE` 更新 C 区数字。
  - 点击刻度某位置 → 直接 `TUNE` 到该频点。
  - 物理 LEFT/RIGHT 键（114/102）→ ±100 kHz 微调（触摸屏外的可达性必备）。

#### E. 信号强度与 RDS 文本（352–413）

| 元素 | 来源 | 规格 |
|---|---|---|
| RSSI 五格信号条 | `GETRSSI` | 轮询周期建议 500ms；强弱阈值**需实测标定**（当前无样本，先在实现时用 `/tmp/fmtest` 打印原始值找分界线） |
| RT 滚动字幕 | `rds_get_rt()` | 64 字符，超宽时滚动；无 RDS 隐藏 |

> ⚠️ RSSI 阈值必须**实测标定**，不要照搬网上通用的 `-85dBm` 之类数值——本机 `GETRSSI` 返回的是驱动原始值，量纲未知。

#### F. 控制区（430–590）

五行位 3 类按钮（建议使用 96×96 圆形按钮，纵向居中一 ribbon）：

| 按钮 | 图标 | 行为 | 驱动调用 |
|---|---|---|---|
| 上一频点 ◀◀ | `LV_SYMBOL_PREV` | `SEEK` down（找下一个强信号） | `SEEK(dir=0)` |
| 搜索 ⟲ | `LV_SYMBOL_REFRESH` | 短按=单次 seek；**长按=自动全频扫描** | `SEEK` / `SCAN` |
| 静音 🔇 | `LV_SYMBOL_MUTE` | 切换 FM 静音 | `MUTE` |
| 下一频点 ▶▶ | `LV_SYMBOL_NEXT` | `SEEK` up | `SEEK(dir=1)` |

> 自动扫描：**长按 ⟲ ≥ 800ms** 触发，扫描期间按钮变为「停止」，`STOP_SCAN` 可中断。
> 扫描总线也建议其余按钮 disabled，避免状态机混乱。

#### G. 收藏频道列表（606–1110）

`lv_list` 实现，每行高度 **62px**（两行文字各 31px）：

```
┌───────────────────────────────────┐
│ ★  97.4 MHz                  [✕]  │
│    北京音乐广播 / α PS             │
└───────────────────────────────────┘
```

- 左侧频点 + 台名（台名无 RDS 时留空）
- 右侧删除按钮 `LV_SYMBOL_CLOSE`（或长按行弹出删除确认，防误触）
- 点击行 → `TUNE` 到该频点并滚动列表置顶
- 数据持久化见 §5.6

#### H. 音量与声道（1128–1264）

| 元素 | 说明 |
|---|---|
| 音量滑条 | `lv_slider`，范围绑定 `SETVOL/GETVOL`（取值范围待探明，见 §1.2 待验证项 3） |
| 静音按钮 | 与 F 区静音联动（同一状态，双向同步） |
| 输出声道指示 | 文本控件，显示当前竞争者胜出的声道：扬声器 / 耳机 / 蓝牙 A2DP |

### 4.3 页面交互流程（状态机）

```
         ┌────────────┐
         │  Z1 未启动  │ ← 首次进入 / daemon 未拉起
         └─────┬──────┘
               │ 调用 open
               ▼
         ┌────────────┐
    ┌───▶│  Z2 就绪    │ 无合适音频通路 → 提示插入耳机 / 弹声道窗
    │    └─────┬──────┘
    │          │ TUNE 到上次频点
    │          ▼
    │    ┌────────────┐
    └────│  Z3 播放中  │◀── TUNE / SEEK / 列表点击 / 刻度微调
         └──┬──┬──┬───┘
    静音 ───┘  │  └─── 长按 ⟲ → Z4
               │
            返回键 → 后台（见 §5.5）不改大学出版社 Z3
               │
               ▼
         ┌────────────┐
         │  Z4 扫描中  │ 进度条百分比 + 已发现台数；STOP_SCAN 或完成 → Z3
         └────────────┘
```

### 4.4 页面注册范式（严格遵守既有约定）

新增 `lv_pages/radio_page.c` / `radio_page.h`：

```c
/* radio_page.h */
extern lv_page_t g_radio_page;

/* radio_page.c —— 结构与 bluetooth_page.c:1118 完全一致 */
lv_page_t g_radio_page = {
    .root = NULL,
    .page_name = "radio",
    .onCreate  = radio_page_on_create,
    .onResume  = radio_page_on_resume,   /* 恢复时会重新拉 UI 状态：现在的频点、RSSI */
    .onPause   = radio_page_on_pause,    /* 必须停掉所有 lv_timer，但【不停播放】 */
    .onDestroy = radio_page_on_destroy,
    .onActivityResult = NULL,
    .user_data = NULL,
    .request_code = -1,
    .result_code = 0,
    .result_data = NULL,
    .launch_flags = LV_PAGE_FLAG_DEFAULT,
};
```

> ⚠️ 两条红线（`lv_pm/lv_page_manager.h` 注释原文）：
> 1. `onDestroy` 中**必须**释放自己的定时器、回调，并把自建全局 UI 指针置空；
> 2. `onDestroy` 中**不要**删除 `page->root`，根节点由页面管理器统一删除。
>
> 另：SIM 页面栈最大深度 8，收藏列表面可用 `LV_PAGE_FLAG_NO_HISTORY` 之类按需调整。

### 5.3 FM daemon 接口（镜像 `bt_user_daemon` 的既有范式）

蓝牙 daemon 用的是 unix socket + 纯文本命令（发 `state` / `on` / `off`，回 `OK ...\n`），FM 建议完全照抄该范式：

| 项目 | 蓝牙（既有，参照） | FM（新增，建议） |
|---|---|---|
| socket 路径 | `/tmp/bt_ctl.sock` | **`/tmp/fm_ctl.sock`** |
| 权限 | `chmod(SOCK_PATH, 0666)` | 同 |
| 协议 | 文本命令 + `\n` 结尾，回 `OK <payload>\n` | 同 |
| 典型命令 | `state` / `on` / `off` / 扫描相关 | `state`、`open`、`close`、`tune <freq_khz>`、`seek <0|1>`、`scan`、`stopscan`、`rssi`、`vol <n>`、`mute <0|1>`、`rds` |

> 🔒 **必须设超时**：做 socket I/O 的 LVGL 定时器回调**必须** `SO_RCVTIMEO` / `SO_SNDTIMEO`（建议 200ms），
> 否则 daemon 卡住会直接冻结 UI 线程。这是本项目蓝牙页踩过的硬教训。

### 5.4 声道仲裁（FM / A2DP / 本地播放互斥）—— 重点设计

三种 FM 音频输出路径由驱动暴露：

| 路径 | 开关 | 适用场景 | 优先级建议 |
|---|---|---|---|
| **模拟/内部 codec** | `ANA_SWITCH` | 本机扬声器 / 耳机直出 | 默认 |
| **I2S** | `I2S_SETTING` / `GET_I2S_INFO` | 需走外部 codec 时 | 备选（**需实测确认是否可用**） |
| **Over BT** | `OVER_BT_ENABLE` | FM 声音从蓝牙耳机/音箱出 | 蓝牙已连接时可选 |

**仲裁规则建议**（在 LVGL 主进程实现单一"音频焦点"模块，daemon 只管设备）：

| 当前占用者 | 新申请者 | 处理 |
|---|---|---|
| 空闲 | FM | 直接获取；按 §5.4 表选默认路径（耳机插入→耳机，否则扬声器） |
| 空闲 | A2DP | 直接获取 |
| FM | A2DP | **FM 自动 mute（不 close）**，A2DP 结束后询问是否恢复 FM |
| A2DP | FM | 弹确认框：「蓝牙正在播放，是否切到收音机？」→ 同意则暂停/断开 A2DP 后 FM 接管 |
| 本地播放（音乐/视频） | FM | 停止本地播放 → FM 接管 |
| FM | 本地播放 | FM mute → 本地播放接管 |

> ⚠️ `OVER_BT_ENABLE` 是本设计的**关键不确定项**：它到底是把 FM 音频"送给已连接的蓝牙设备"，
> 还是"允许 FM 与 BT 共存"，尚未经读码确认。
> **实现前必须先用最小程序试探该 ioctl 的行为**，再写仲裁逻辑。这条不确认就动手，很可能会错测。

### 5.5 后台播放与息屏保持

| 需求 | 实现要点 |
|---|---|
| 返回桌面继续播放 | `onPause` 只停 UI 定时器/回调，**不调 close、不静音**；播放状态由 daemon 持有，与页面生命周期解耦 |
| 页面彻底销毁 | `onDestroy` 同样不停台（理由同上）；只有用户显式按关闭或关机才 stop |
| 息屏保持播放 | 息屏由系统背光管理；FM 是 daemon 在播，不依赖 LVGL 心跳。**需实测**：确认息屏不会触发 `fm_suspend`（驱动里有 `fm_suspend` / `fm_resume`，是被 PM 挂起的入口，务必验证系统 suspend 时 FM 是否掉台） |
| 开机自启 | 参考既有 `bt_user_daemon` 的 openrc 自启写法；自启前必须先确认 WiFi 链已拉起（固件依赖，见 §5.2 第 0 步） |

> ⚠️ 驱动符号表里有 `fm_suspend` / `fm_resume` 两个**静态**函数（`t` 而非 `T`），说明驱动实现了 dev_pm_ops。
> 系统挂起时 FM 很可能会被一起挂起。若产品要求息屏续听，需要额外处理（wakelock 或禁止 suspend），此项**必须实测**，不可假定。

### 5.6 状态持久化

建议路径 `/etc/fm_radio.conf`（或沿用项目既有配置存放约定），JSON/INI 二选一：

| 字段 | 说明 |
|---|---|
| `last_freq` | 上次收听频点（kHz），开机恢复到该频点 |
| `volume` | 上次音量 |
| `muted` | 静音状态 |
| `rds_on` | RDS 开关（建议常开） |
| `band/region` | 地区频段（P2） |
| `favorites[]` | 收藏列表：`{freq, name}` |

写入时机：退出程序、切换频点后 debounce 1s、增删收藏立即写。

## 6. 一句话总结

> **收音机不是一个"从零写一个 FM 协议栈"的活儿**：
> 本机 **Marlin2 芯片的 FM 部件 + `marlin_fm.ko` 驱动已经现成在跑**（`/dev/fm` 也已经在 `/proc/misc` 注册），
> 真正的工作量集中在**三件事**——写一个镜像 `bt_user_daemon` 范式的 FM daemon 把 ioctl 包装成 socket 命令、
> 按 31px 行高网格画出收音机页、以及做好 **FM / A2DP / 本地播放的声道仲裁**。
> 动手前先跑完 §1.2 标注的三项待验证确认，尤其是"要不要播耳机当天线"和 `OVER_BT_ENABLE` 的真实语义。
