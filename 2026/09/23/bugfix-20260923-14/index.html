bugfix, 模拟器

bugfix_20260923_14 — GBA 退出后”卡死”（页翻转残留：屏幕定格在游戏画面）

  • 日期：2026-09-23
  • 现象：GBA 游戏退出后屏幕不黑（显示游戏画面），但界面永远回不来、按键像失灵，
    只能重启应用。用户描述为”不黑屏了，直接卡死”。偶发 —— 有时正常，有时必卡。
  • 影响面：lv_pages/gba_game_page.c、extern/miniretro/miniretro_gba.c（GBA 前端）
  • 是否影响 FC：不影响（FC 用原版 miniretro，它从来不翻页）

1. 背景：两个驱动对”页”的理解不一致

设备 framebuffer 有 3 个虚拟页（yres_virtual=3840 = 3×1280）。

谁 怎么用 fb0
LVGL（lv_linux_fbdev） 只用 mmap 基址绘制 = 永远写第 0 页；vinfo.yoffset 在 init 时设 0 后再不改；源码里 FBIOPAN_DISPLAY 零命中
GBA 前端（miniretro_gba） 用 FBIOPAN_DISPLAY 双缓冲页翻转消撕裂 → 前台在第 0/1 页之间来回切

关键推论：只要退出时前台停在第 1 页，LVGL 画什么都看不见 ——
因为 LVGL 永远往第 0 页写，而屏幕显示的是第 1 页。

2. 根因

  1. 前端每渲染一帧就翻一次页，**前台页是 0 还是 1 取决于”退出那一刻”**。
    实测抓帧：启动游戏后依次测到 yoffset=1280 → 0 → 1280 → 1280 → 1280（同一局游戏内）。
  2. 前端退出时本会在 fb_restore() 里翻回第 0 页（定点实测：SIGTERM 后 0.4s yoffset 由 1280 变 0），
    但父进程 gba_exit_to_list() 在 **SIGTERM 后 120ms 就补 SIGKILL**；
    而前端收尾里包含 core_deinit() —— 把 .sav 电池存档落盘到 SD 卡，写卡慢时远超 120ms。
  3. 一旦被 SIGKILL 打断 → 翻页没做 → 前台永久停在第 1 页 → 屏幕定格游戏画面 → “卡死”。

这解释了为什么它偶发：存档早就在页缓存里 → 收尾 <120ms → 正常；
真要写 SD 卡 → 被杀 → 卡死。

3. 证据

证据 内容
源码 lv_linux_fbdev.c:174 dsc->vinfo.yoffset = 0;（此后不改）、grep -n 'PAN' 零命中
抓帧 图 shots/final/01..10：运行期 yoffset 在 0/1 间切换
定点实验 单独跑 miniretro_gba：运行中 yoffset=1280 → SIGTERM 后 0.4s →0（说明前端收尾能翻页，问题只在”有没有机会走到”）
残留取证 shots/guard/01：重启应用后抓到的”桌面”其实是页1 里的上一局游戏画面（yoffset=1280）—— 正是卡死的物质形态
排除项 前端退出日志完整（收尾完成 t=30.8ms）、无僵尸、无崩溃循环、hardware_keys 的 EVIOCGRAB 幂等正常

4. 修复（三层兜底，全部”幂等 + 只在异常时才有动作”）

4.1 前端 miniretro_gba.c — fb_restore() 改为无条件翻回第 0 页

去掉”先读 yoffset、非 0 才翻”的分支：翻到第 0 页本身是幂等操作，
判断只会多一个可能出错的分支（虽然实测本驱动回读可靠，但没必要依赖）。
失败/翻不动时打印 ★ 翻回第0页失败，便于现场定位。

4.2 GBA 页 — 新增 gba_reset_fb_page()，父进程自己兜底翻页

打开 /dev/fb0，若 yoffset != 0 就 FBIOPAN_DISPLAY 到 0。
无论前端有没有被打死都成立 —— 这是治本的一层。在 3 处调用：

调用点 作用
gba_wait_thread() 恢复段（set_lvgl_paused(false) 之前） 游戏退出 → 恢复 UI 前先保证可见页 = 第 0 页
gba_on_destroy() 页面离场时再兜一次
gba_on_create() 进页面先归零（若上次异常留下页1 残留）

4.3 补刀时间 120ms → 600ms

给”落存档 + 翻页”留出时间。补刀必须保留（子进程真挂死时，没有 SIGKILL 会让阻塞的
waitpid 永不返回）。这 600ms 只花在按键线程里，不拖慢 UI 恢复。

4.4 恢复重绘后补一次 lv_refr_now(NULL)

只 invalidate 的话要等下一轮 lv_timer_handler 才真正出图；立即刷一帧，
消除”标志被消费、画面却没画回来”的窗口。

5. 验证

项 结果
定点：前端运行中 / SIGTERM 后 yoffset 1280 → 0 ✓
关键推论（运行期会在页1） 实测同一局内多次采到 yoffset=1280 ✓
编译 前端 RC=0、主程序 MAKE_RC=0 / ERR=0 ✓
部署 原子替换 BIN_OK；设备源码 gba_reset_fb_page×6、前端”无条件翻回”×1 ✓
运行态 lvgl_demo×1 + lvgl_watchdog×1；退出后 yoffset=0；无僵尸 ✓
正常路径 兜底日志不出现（前端自己已翻回 0）→ 兜底是纯保险，不改变正常行为 ✓

6. 反模式记录（本次新增，已并入 skill）

  • 多缓冲页翻转必须”退出时归位”：只要有一个消费者（LVGL）不做翻页、
    而另一个生产者（外部播放器/模拟器）做翻页，    退出时不清算前台页 = 永久黑屏/定格    。
    且归位责任不能只交给会被强杀的子进程 —— 父进程必须能自己兜底。
  • 给子进程的 SIGKILL 时限要考虑它的落盘开销（存档/截图/日志刷盘），
    否则”以为在防挂死，实际在制造故障”。

7. 遗留

  • 退出到恢复 UI 仍有 ~400ms（内核回收 evdev fd 的固有开销），刻意保留（与 FC 一致）。
  • 本文件描述的三层兜底中，只有”前端无条件翻页”需要重编前端；另三层都在页面侧。
  • 若将来给 FC 页也上双缓冲（当前 FC 前端不翻页、无此问题），必须同时搬这三层兜底。
