GBA退出偶发卡在游戏画面_买单键漏给UI层

wlb
2026-09-23
bugfix, 模拟器

bugfix_20260923_15 — GBA 退出”偶发卡在游戏画面”（买单键漏给 UI 层 → 本页被弹掉 → 无人重绘）

  • 日期：2026-09-23
  • 现象：按买单退出 GBA 游戏，miniretro 进程确实退出了，但画面有时不刷新、停在游戏画面上；有时又能正常回到游戏列表。概率性故障。
  • 触及文件：lv_pages/gba_game_page.c（退出流程）、extern/miniretro/miniretro_gba.c（fb_restore()）
  • 一句话结论：三处协同缺陷 —— 退出期间按键线程被 sleep 占住 → 残留按键漏给 UI 层 → 本页被当”返回”弹出 → 负责整屏重绘的定时器随页面消失 → 屏幕留在游戏画面。

1. 背景：这次和上一版（bugfix_14）不是同一个问题

bugfix_14 修的是”前端退出时前台停在第 1 页，而 UI 层只画第 0 页 → 屏幕定格”。那一版加了父子双层兜底翻页，翻页本身已经可靠（日志可见 fb pan 回第0页(无条件)）。

本次的关键区别：进程确实退了、页也确实翻回第 0 页了（实测 yoffset=0），但屏幕内容仍是游戏画面。
也就是说问题已经从”翻页”转移到了”谁来把新界面画上去“。

2. 根因（三处协同，缺一不成立）

2.1 买单键漏给 UI 层，把本页一起”返回”掉了

旧版 gba_exit_to_list() 在按键线程里 usleep(600ms) 等补 SIGKILL，于是：

  1. 这 600ms 内没人读 /dev/input/event0，输入事件堆在内核缓冲里；
  2. 前端前端约 30ms 就退出了，内核回收 evdev fd 约 450ms，wait 线程随即摘掉按键拦截器；
  3. 按键线程醒来时拦截器已不在 → 堆着的”买单松开”事件一股脑涌进 UI 层；
  4. 它被当成”返回”键（ESC）→ 本页被弹出。

2.2 页面一销毁，负责整屏重绘的定时器也跟着没了

gba_timer_cb 是挂在本页上的（lv_timer_create），页面销毁时 lv_timer_del 把它删掉。
于是”整屏重绘”这件事依赖页面存活 —— 2.1 一旦发生，就再没有人 lv_obj_invalidate + lv_refr_now。

2.3 前端把游戏画面写进了 UI 层的地盘

fb_restore() 旧版在翻回第 0 页之后，还把前台页整页 memcpy 到第 0 页（”定格最后一帧”）。
第 0 页正是 UI 层永远绘制的那一页 → 一旦没人重绘，屏幕上留下的就是游戏画面。这就是本故障的物质形态。

3. 证据（设备日志）

  • [nav] key=27（27 = LV_KEY_ESC = 买单）证明买单键确实漏到了 UI 层；
  • 紧随其后的 [pm] 页面 'gba_game' 离场 证明本页被弹出；
  • 同一份日志里另一次退出没有 [nav] key=27 → 这正是”有时好、有时坏”的来源；
  • 故障现场实测 yoffset=0（页已归位）→ 排除 bugfix_14 那类”页没翻回来”，锁定”无人重绘”。

4. 修复（8 处改动）

4.1 按键线程立刻返回，补刀交给 wait 线程

gba_exit_to_list() 只发 SIGTERM 就返回 —— 按键线程必须马上回去继续读键盘，把退出期间产生的残留事件吞掉（那时拦截器还在）。

4.2 整屏重绘改用 lv_async_call，不再依赖页面存活

新增 gba_repaint_async()，由 lv_async_call 排队给主线程执行：

lv_async_call 的回调不依附任何页面对象，页面在不在都会执行；此刻 lv_screen_active() 已经是该显示的页面，整屏重绘即可覆盖残留。

4.3 收尸改非阻塞轮询（顺带把 UI 恢复提前约 570ms）

wait 线程先 waitpid(WNOHANG) 轮询最多 600ms，超时未死才补 SIGKILL，再阻塞收尸。
判据仍然只有一个硬事件——子进程真的消失；超时那一刻不是”当作它退了”，而是强制它死。绝不设”跑满 N 秒就算退出”的上限。

4.4 前端去掉整页 memcpy

双缓冲下第 0 页装的本就是游戏的上一帧，视觉上与”最后一帧”没有差别；去掉后既省掉 3.7MB / ~15ms 的拷贝，也消除了”往 UI 层地盘写外部内容”这个竞争源。

4.5 页面销毁路径同样兜底

按右上角”返回”按钮回桌面走的是 gba_on_destroy，同样补一次 lv_async_call 重绘。

4.6 gba_on_destroy 先 SIGTERM 再 SIGKILL

原实现直接 SIGKILL，会把 .sav 存档写一半断在 SD 卡上；改为最多等 300ms 再补刀。

4.7 拦截器摘除顺序后移

hardware_keys_set_interceptor(NULL, NULL) 移到恢复段最后，尽量让按键线程先吞干净残留事件。

4.8 gba_timer_cb 聚焦前校验对象有效

lv_group_focus_obj(s_gba.btns[0]) 前加 lv_obj_is_valid。

5. 验证

  • 前端 sh build.sh → FRONT_RC=0；主程序 make -j2 → MAKE_RC=0 / 0 error
  • 原子替换 BIN_OK，重启后单实例；build/lvgl_demo 与 /usr/local/bin/lvgl_demo 同大小同时间戳
  • 源码校验：gba_repaint_async 5 处命中、lv_async_call 4 处命中、旧 usleep(600...) 调用已无（仅剩说明性注释）
  • 待实机复测：连续多次”进游戏 → 买单退出”，每次都应回到游戏列表且画面立即刷新

6. 反模式记录

  1. 让”界面恢复”依赖某个页面对象（定时器/控件）存活 —— 页面一旦先被销毁，恢复就静默失效，且没有任何报错。
  2. 在自己线程里 sleep 等补刀 —— 阻塞期间没人消费输入，残留事件会在拦截器摘除后一起涌入 UI 层。
  3. 往”别人的页面”写内容（往 UI 层永远绘制的那一页拷帧）—— 只要对方重绘时序有一点偏差，残留就永久留在屏幕上。

7. 遗留

  • .sav 落盘：本次给 on_destroy 加了最多 300ms 的等待窗口，但未做存档完整性校验。
  • FC 侧不受影响（独立前端 + 独立页面），本轮未改动。
