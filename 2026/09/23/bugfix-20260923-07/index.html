GBA退出游戏时画面卡顿僵住

wlb
2026-09-23
bugfix, 模拟器

bugfix_20260923_07 — GBA 退出游戏时画面卡顿/僵住

  • 日期：2026-09-23
  • 模块：GBA 游戏页 / miniretro.c 退出路径 + lv_pages/gba_game_page.c
  • 影响：所有 GBA 游戏退出、以及 FC 游戏退出（共用 miniretro）

1. 问题现象

按”买单”键（116）退出游戏时画面卡住/花屏几秒才回到列表，有时残留半屏游戏画面。

2. 影响范围

  • GBA / FC 游戏退出返回列表
  • 后续 LVGL 画面（残留会一直糊在原处，直到该区域被重绘）

3. 根因分析

三处叠加：

  1. miniretro 没有 SIGTERM 处理
    父进程 gba_exit_to_list() 只 kill(pid, SIGTERM) 后 120ms 就 SIGKILL 兜底。
    SIGTERM 默认行为是直接杀进程 → 主循环的 cleanup 段永远不执行（fb_restore/munmap 全被跳过）。
  2. fb 停在翻转页
    双缓冲用 FBIOPAN_DISPLAY 换页，被杀时前台页停在 yoffset=1280（第 1 页），
    而 LVGL 只会往第 0 页画 → 屏幕一直显示第 1 页那张旧游戏帧。
    实测取证：kill -TERM 后读 FBIOGET_VSCREENINFO 得 yoffset=1280（修复后为 0）。
  3. LVGL 只刷脏区
    项目已知结论：LVGL 只 flush 自绘区、不清整屏。miniretro 直写 fb0 留下的像素不在 LVGL 的脏区里，
    所以即使恢复绘制，残留也擦不掉。
    另外游戏画面上下各有 100px 信箱黑边（out_w=720 → out_h=1080）不属于输出区，
    开跑前不清屏会残留 LVGL 最后一帧的 UI，看着像”花屏带”。

4. 修复方案

  • miniretro.c：新增 on_quit_signal()，安装 SIGTERM/SIGINT 处理器，只置 quit=1，
    让主循环自然退出并走完 cleanup。
  • miniretro.c：新增 fb_restore() —— FBIOPAN_DISPLAY 把 yoffset 归 0，并把整块虚拟显存清零。
    在退出 cleanup 和进入主循环前各调用一次（后者顺手清掉信箱区残留）。
  • gba_game_page.c：gba_exit_to_list() 的宽限期由 120ms 放宽到 250ms，
    给优雅退出留出收尾时间，超时仍 SIGKILL 兜底。

5. 验证方法与结果

设备端受控测试（kill -TERM 后立刻读 fb 状态）：

日志出现 [miniretro] 退出 即证明走到了 cleanup（含 fb_restore()）而不是被 SIGKILL 打断。

6. 回归风险

  • SIGKILL 兜底路径仍保留：若子进程异常卡死，250ms 后强杀，此时 fb 不会复位，
    但仍由 gba_timer_cb 的整屏重绘 + LVGL 刷新救场（比修复前只多 130ms 延迟）。
  • 清屏是对整块虚拟显存（3 页 × 1280 行）memset，约 11MB，一次性开销可忽略。
