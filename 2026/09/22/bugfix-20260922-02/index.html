收音机刻度尺全挤在左侧

wlb
2026-09-22
bugfix, 收音机

bugfix_20260922_02 — 收音机页刻度尺所有刻度挤在左侧

关联提交：221fa7d

现象

新增的「FM 收音机」页面（lv_pages/radio_page.c）中，D 区频率刻度尺（覆盖 88~108 MHz，
应横向铺满卡片）所有刻度线、数字标签、收藏方块全部挤在卡片最左侧约 10px 内，
肉眼看起来就是一小坨竖着堆叠的重影；右侧整片空白。

影响范围

  • 只影响 radio_page.c 的刻度尺（rp_ruler_rebuild() / rp_ruler_pointer_update()）。
  • 同页面其它分区（标题栏、当前频点、信号柱、控制按钮、收藏列表、音量条）不受影响 ——
    它们的坐标是写死的常量，不依赖运行时取宽。
  • 不影响任何其它页面。

根因

LVGL 9 的 lv_obj_get_width() 返回的是缓存坐标区 obj->coords，而不是刚 lv_obj_set_size() 设进去的值。

证据（设备端源码）：

coords 只在布局周期（lv_obj_update_layout / 刷新）里才被刷新。而
rp_ruler_rebuild() 是在 onCreate() 里紧跟着 lv_obj_set_size(marks, w, 78) 调用的，
此刻布局还没跑过，coords 仍是全 0 → lv_obj_get_width() 返回 0。

代码里还有一句”兜底”把问题藏得更深：

于是 21 个刻度 + 6 个标签 + 5 个收藏方块全部落在 x=0~9，视觉上就是左侧一坨。

定位过程

  1. 先看整页截图：其它分区都对，只有刻度尺塌了 → 先怀疑是容器布局（flex）接管了子对象坐标。
  2. 在 rp_ruler_rebuild() 里加临时探针，直接打印运行时几何： 实测输出： → get_width=10 而不是应有的 652（=720-24-44）。坐标本身没问题，就是宽度取值错了。
  3. grep lv_obj_get_width 到源码，确认它读 coords，锁定根因。
  4. 排除过的错误方向：
    • 曾怀疑 lv_obj_set_layout(marks, LV_LAYOUT_NONE) 没生效被 flex 接管 → 不是，set_pos 本身生效了；
    • 曾怀疑是”标签 x-12 越界” → 那是另一个真实但次要的问题（见下”注”）。

解决办法

把创建时显式设过的宽度缓存下来，不再依赖运行时取宽（remote_src/radio_page.c）：

三处用宽度的代码（刻度 x、收藏方块 x、指针 x）统一改走 rp_ruler_width()。

同时修掉同一函数里的第二个 bug：指针原本是 marks 的子对象，而
rp_ruler_rebuild() 第一件事就是 lv_obj_clean(marks) —— 会把指针一起删掉，
s_rp.ruler_pointer 变成悬垂指针。现改为在 clean 之后重新创建指针并立即
rp_ruler_pointer_update()。

注（顺带修的第三个问题）：刻度 x 原本按 [0, w] 满宽映射，标签以中心对齐，
导致最右的 “108” 被卡片边缘裁掉（实测截图只显示 “10”）。加左右内缩
RP_RULER_PAD 14 后两端标签都能完整显示。

验证

  1. 重新编译部署：ssh_tools/radio_dev.py remote_src/radio_page.c:lv_pages/radio_page.c
  2. 用标准键码注入导航进收音机页（见 bugfix_03 的键码说明），或直接 ssh_tools/radio_page_snap.py
  3. 人眼看物理屏（截图仅作留档）：刻度尺横向铺满，88/92/96/100/104/108 六个标签
    全部完整可见，偶数 MHz 长刻度 / 奇数 MHz 短刻度交替，5 个收藏红方块与当前频点指针
    落在正确比例位置（87.5 在最左、106.1 在偏右）。
  4. 局部放大复核：python ssh_tools/zoom_crop.py shots/_fb_tmp.raw shots/zoom_ruler2.png 0 262 720 108 2
    → 结果确认修好。

经验教训

  1. LVGL 9 里 lv_obj_get_*() 系列（width/height/x/y）读的都是缓存 coords，不是”刚设进去的值”。
    凡是”创建对象 → 立刻按它的尺寸算子对象坐标”的场景，都必须自己缓存那个尺寸，
    或者先显式 lv_obj_update_layout(obj)。这是一个会静默出错（返回 0）的坑。
  2. **”兜底” if 会把 bug 从”崩溃/明显异常”变成”看起来能跑的错值”**：
    if (w < 10) w = 10; 让 0 变成了 10，症状从”什么都没有”变成”全挤在左边”，
    多花了一轮才定位。兜底值要么等于正常量级，要么就该直接报错。
  3. lv_obj_clean(parent) 会删掉 parent 的所有子对象。常驻句柄不能挂在会被
    clean 的容器下；否则必须显式地在 clean 之后重建。
  4. 给容器子对象设坐标前，先确认容器的 layout 是 NONE（本页其它卡片恰好没被 flex 接管）。
  5. 调试界面几何问题的性价比最高手段：在函数里打一行 fprintf 把运行时数字打出来，
    比对着截图猜快一个数量级。
