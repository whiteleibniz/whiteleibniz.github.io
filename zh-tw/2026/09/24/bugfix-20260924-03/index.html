bugfix_20260924_03 — 「切換桌面」橫屏只顯示一半（根因是 pivot 未設，不是 transform 不可用）

關聯提交：2341fad

  • 日期：2026-09-24
  • 影響範圍：lv_pages/launcher_page.c（橫屏桌面）、main.c（回滾）、lv_pages/launcher_page.h
  • 本文同時推翻 bugfix_20260924_02 的結論。
  • 結論一句話：transform 在這臺設備上一直是可用的；02 的白屏根因是
    transform_pivot 沒設（默認是對象左上角，1300x720 畫布繞左上角轉 90° 後整個轉出可視區）。
    橫屏正確做法 = 與 lv_pages/fc_game_page.c 完全同款：1280x720 邏輯畫布 + lv_obj_center +
    transform_pivot=50% + transform_rotation=900。

1. 現象與訴求

  • 02 之後橫屏改用「flush 層整屏轉置」（lv_hardware/fb_rotate.c + 運行時改顯示分辨率）。
  • 用戶反饋：**”桌面只顯示一半”**，並要求 **”參照 FC 遊戲 page 源碼實現橫屏顯示”**。

用戶的提示本身就是正確答案：fc_game_page.c 是同項目里長期在用的橫屏頁面，
它用的正是 transform_rotation。

2. 定位：為什麼 02 會得出”transform 不可用”

把兩次實現放到一起 diff，差異只有一行：

02 的失敗版本 fc_game_page.c（一直正常）
邏輯畫布 1280x720 1280x720
lv_obj_center(canvas) 有 有
transform_pivot_x/y = lv_pct(50) 沒有 有
transform_rotation 900 900
父容器 頁面 root 頁面 root

fc_game_page.c 的註釋裡早就把答案寫著：

旋轉支點必須顯式設成中心！這臺 LVGL style 默認的 transform_pivot 是對象左上角，
不設的話畫布會繞左上角轉出屏幕外，整頁一個像素都看不到。

“整頁一個像素都看不到” = 02 觀察到的白屏。根因一直都在註釋裡。

3. 根因

  1. 直接原因：transform_pivot 未設 → 默認 pivot = 對象左上角。1280x720 畫布繞左上角轉 90° 後，
    可視區域落在屏幕外 → 看起來”容器和卡片全部不見”。
  2. 02 的誤判鏈：
    • 觀察到”帶 transform 的對象不繪製”（現象正確）；
    • 但把它上升為設備級定性“這臺設備的 transform 渲染路徑不可用”（結論錯誤）；
    • 反例就在同一個倉庫裡（fc_game_page.c），當時沒有去搜。
    • 於是棄用了正確方案，改做整屏 framebuffer 轉置 —— 那條路又引出”只顯示一半”，多花兩輪。

4. 修復

4.1 橫屏桌面改回畫布旋轉（lv_pages/launcher_page.c）

  • 卡片/狀態欄/標題全部建在這塊畫布內，座標用未旋轉的邏輯座標；
  • 進入/退出 = 建/刪畫布，不再碰顯示分辨率與 flush。

4.2 旋轉後的座標系與方向（本次實測確認）

畫布轉 90° 後：**物理 (px, py) = (720 - ly, lx)**，所以

  • 視覺 x ≡ 邏輯 x ⇒ 卡片沿邏輯 x 排列時，方向鍵不需要任何換算，
    app_runtime_set_ui_rotation(0)（原按 FC 頁設 1 會讓左右鍵反向）。
  • 視覺 y = 720 - 邏輯 y ⇒ 「視覺上方」= 邏輯 y 小。需要跟著改的地方：
    元素 視覺期望 邏輯做法
    卡片標題 卡片下方 貼 cell 頂部（LV_ALIGN_TOP_MID, 0, 0）
    玻璃反光條 卡片頂部 貼 box 底部（LV_ALIGN_BOTTOM_MID, 0, -(10+k*22)）
    陰影 向下 shadow_ofs_y 取負
    根容器漸變”上深下淺” 垂直 LV_GRAD_DIR_HOR

4.3 回滾 fb_rotate（main.c）

  • 恢復原生 fb_flush_cb（含 R/B 字節交換）——fb_rotate 版本漏了 R/B 交換，即使畫面出來顏色也會反；
  • 移除 fbr_init / fbr_map_pointer / 顯示分辨率切換；
  • 刪除 lv_hardware/fb_rotate.c / .h（Makefile 用 wildcard，刪文件即徹底摘除）。

4.4 返回鍵（用戶 7 條反饋中的第 4 條）

不再依賴 fbr_request_exit，改為 launcher 對外提供：

main.c 的兩條 ESC 路徑（物理鍵 / USB 鍵盤）都改成
if(launcher_cover_active()) { launcher_cover_close(); return; }
⇒ 橫屏桌面按「買單」鍵先退回豎屏桌面，而不是退出桌面。

5. 驗證

  • 進入橫屏抓幀（ssh_tools/grab_screen.py）：**全屏非黑 100%**，不再是白屏/半屏；
    畫面含 3 張卡片（左/中放大/右）、狀態欄四要素（時間、WiFi、藍牙、電量）。
  • 修正裝飾方向後再抓幀：反光條到卡片頂部、標題到卡片下方、圖標居中、陰影向下。
  • 迴歸：刪掉臨時自驗開關重啟 → 豎屏桌面 20 個圖標 + 狀態欄全部正常，橫屏改動沒有破壞原桌面。
  • 設備端長期觀察：進程存活、無 segfault、日誌 [cover] landscape on, items=N canvas=1280x720 rot=900。

6. 經驗（反模式記錄）

  1. ★ 下”設備/平臺不支持 X”的定性前，先在本項目裡搜 X 的成功用例。 有先例 → 逐項 diff（尺寸 / 父容器 / pivot / 繪製順序 / 狀態），差異點即根因。
    一次失敗 ≠ 能力不存在；把失敗上升為定性 = 用一個更大的錯誤掩蓋小錯誤。
  2. ★ 註釋要按作用域讀。/* transform disabled */ 寫在 launcher_start_zoom() 裡，
    意思是”這個按下縮放動畫被關掉”，不是“整機 transform 不可用”。
    02 把它當成了後者的證據，方向就反了。
  3. 用戶的指向往往是最短路徑。用戶說”參照 FC 遊戲 page 源碼實現”，
    等價於”倉庫裡有現成正確實現” —— 應當第一時間去讀那份源碼，而不是自己另起一套。
  4. 換了實現就要重新驗顏色。fb_rotate 版漏掉 R/B 交換，說明”重寫 flush 路徑”時必須
    逐項對照原實現（字節序、stride、頁翻轉）。
  5. 推翻舊結論後必須回改已歸檔的文檔與 Skill，否則錯誤結論會汙染下一次判斷
    （本次已同步修正 ref_LVGL_頁面框架.md 與 gui-render-blank-diagnosis Skill）。

7. 遺留

  • 橫屏卡片尺寸（未選中 300、選中 ~492 邏輯像素）與狀態欄位置已可用；圖標仍受限於
    **最大字號 lv_font_montserrat_48**，”圖標更大”需另做大字號字形或圖片型圖標。
  • 橫屏下的 USB 鼠標座標未做映射（當前按豎屏原點採樣）；桌面以物理四鍵導航為主，暫不影響。
  • 調試入口 touch /tmp/cover_auto 後重啟應用可直接進橫屏（源碼中帶 TEMP 註釋），便於後續自測。
