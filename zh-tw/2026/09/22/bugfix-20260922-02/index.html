收音機刻度尺全擠在左側

wlb
2026-09-22
bugfix, 收音机

bugfix_20260922_02 — 收音機頁刻度尺所有刻度擠在左側

關聯提交：221fa7d

現象

新增的「FM 收音機」頁面（lv_pages/radio_page.c）中，D 區頻率刻度尺（覆蓋 88~108 MHz，
應橫向鋪滿卡片）所有刻度線、數字標籤、收藏方塊全部擠在卡片最左側約 10px 內，
肉眼看起來就是一小坨豎著堆疊的重影；右側整片空白。

影響範圍

  • 隻影響 radio_page.c 的刻度尺（rp_ruler_rebuild() / rp_ruler_pointer_update()）。
  • 同頁面其它分區（標題欄、當前頻點、信號柱、控制按鈕、收藏列表、音量條）不受影響 ——
    它們的座標是寫死的常量，不依賴運行時取寬。
  • 不影響任何其它頁面。

根因

LVGL 9 的 lv_obj_get_width() 返回的是緩存座標區 obj->coords，而不是剛 lv_obj_set_size() 設進去的值。

證據（設備端源碼）：

coords 只在佈局週期（lv_obj_update_layout / 刷新）裡才被刷新。而
rp_ruler_rebuild() 是在 onCreate() 裡緊跟著 lv_obj_set_size(marks, w, 78) 調用的，
此刻佈局還沒跑過，coords 仍是全 0 → lv_obj_get_width() 返回 0。

代碼裡還有一句”兜底”把問題藏得更深：

於是 21 個刻度 + 6 個標籤 + 5 個收藏方塊全部落在 x=0~9，視覺上就是左側一坨。

定位過程

  1. 先看整頁截圖：其它分區都對，只有刻度尺塌了 → 先懷疑是容器佈局（flex）接管了子對象座標。
  2. 在 rp_ruler_rebuild() 里加臨時探針，直接打印運行時幾何： 實測輸出： → get_width=10 而不是應有的 652（=720-24-44）。座標本身沒問題，就是寬度取值錯了。
  3. grep lv_obj_get_width 到源碼，確認它讀 coords，鎖定根因。
  4. 排除過的錯誤方向：
    • 曾懷疑 lv_obj_set_layout(marks, LV_LAYOUT_NONE) 沒生效被 flex 接管 → 不是，set_pos 本身生效了；
    • 曾懷疑是”標籤 x-12 越界” → 那是另一個真實但次要的問題（見下”注”）。

解決辦法

把創建時顯式設過的寬度緩存下來，不再依賴運行時取寬（remote_src/radio_page.c）：

三處用寬度的代碼（刻度 x、收藏方塊 x、指針 x）統一改走 rp_ruler_width()。

同時修掉同一函數里的第二個 bug：指針原本是 marks 的子對象，而
rp_ruler_rebuild() 第一件事就是 lv_obj_clean(marks) —— 會把指針一起刪掉，
s_rp.ruler_pointer 變成懸垂指針。現改為在 clean 之後重新創建指針並立即
rp_ruler_pointer_update()。

注（順帶修的第三個問題）：刻度 x 原本按 [0, w] 滿寬映射，標籤以中心對齊，
導致最右的 “108” 被卡片邊緣裁掉（實測截圖只顯示 “10”）。加左右內縮
RP_RULER_PAD 14 後兩端標籤都能完整顯示。

驗證

  1. 重新編譯部署：ssh_tools/radio_dev.py remote_src/radio_page.c:lv_pages/radio_page.c
  2. 用標準鍵碼注入導航進收音機頁（見 bugfix_03 的鍵碼說明），或直接 ssh_tools/radio_page_snap.py
  3. 人眼看物理屏（截圖僅作留檔）：刻度尺橫向鋪滿，88/92/96/100/104/108 六個標籤
    全部完整可見，偶數 MHz 長刻度 / 奇數 MHz 短刻度交替，5 個收藏紅方塊與當前頻點指針
    落在正確比例位置（87.5 在最左、106.1 在偏右）。
  4. 局部放大複核：python ssh_tools/zoom_crop.py shots/_fb_tmp.raw shots/zoom_ruler2.png 0 262 720 108 2
    → 結果確認修好。

經驗教訓

  1. LVGL 9 裡 lv_obj_get_*() 系列（width/height/x/y）讀的都是緩存 coords，不是”剛設進去的值”。
    凡是”創建對象 → 立刻按它的尺寸算子對象座標”的場景，都必須自己緩存那個尺寸，
    或者先顯式 lv_obj_update_layout(obj)。這是一個會靜默出錯（返回 0）的坑。
  2. **”兜底” if 會把 bug 從”崩潰/明顯異常”變成”看起來能跑的錯值”**：
    if (w < 10) w = 10; 讓 0 變成了 10，症狀從”什麼都沒有”變成”全擠在左邊”，
    多花了一輪才定位。兜底值要麼等於正常量級，要麼就該直接報錯。
  3. lv_obj_clean(parent) 會刪掉 parent 的所有子對象。常駐句柄不能掛在會被
    clean 的容器下；否則必須顯式地在 clean 之後重建。
  4. 給容器子對象設座標前，先確認容器的 layout 是 NONE（本頁其它卡片恰好沒被 flex 接管）。
  5. 調試界面幾何問題的性價比最高手段：在函數里打一行 fprintf 把運行時數字打出來，
    比對著截圖猜快一個數量級。
