bugfix_20260923_08 — GBA 畫面紅藍互換（顏色迴歸）

  • 日期：2026-09-23
  • 模塊：GBA 遊戲頁 / miniretro.c 的 scale_rotate90()
  • 影響：所有 GBA 遊戲畫面顏色（FC 遊戲共用同一函數，同樣受影響）

1. 問題現象

遊戲能正常顯示、無條紋無撕裂，但整體顏色紅藍互換：
橙金色的龍珠變成藍色、”DRAGON BALL”標題發藍。屬於本輪改動引入的顏色迴歸。

2. 影響範圍

  • GBA / FC 遊戲全部畫面
  • 不影響 LVGL 桌面與列表頁（那是另一條繪製路徑）

3. 根因分析

本機 framebuffer 的真實字節序為 [R, G, B, X]，
而 LVGL/miniretro 內部打包的像素是 0xAARRGGBB（小端落盤為 [B, G, R, A]），
因此寫 fb 前必須且只能交換一次 R/B 兩個字節。

本輪為提升幀率重寫 scale_rotate90()，改成兩步：

  1. 先把源圖旋轉 90° 寫進小畫布 rot_buf（並把 R/B 交換從第二步挪過來，減少熱循環開銷）；
  2. 再把 rot_buf 縮放拷進 framebuffer。

改動時只在新位置加了交換，忘了刪掉第二步熱循環裡原來那處交換 → 交換執行了兩次 →
R/B 被換回去，等於沒交換 → 紅藍整體反轉。

4. 修復方案

刪除第二步縮放循環裡的 R/B 交換，保持 R/B 交換只在小畫布那一步做一次
（該步只有 src_w × src_h 個像素，GBA 為 38400；放到縮放循環裡是 78 萬次）。
並在該處補註釋說明”第一步已交換過，此處再交換會換回去”，防止再次踩坑。

5. 驗證方法與結果

設備端抓幀解碼成 PNG（os.pread dump + 按 [R,G,B,X] 解 PNG）後目視確認：

版本 龍珠顏色 判定
交換兩次（迴歸版） 藍色 ✗ 紅藍互換
交換一次（修復後） 橙金色 ✅ 正確

6. 迴歸風險

  • 顏色正確性只能靠目視/抓幀確認，不能用”非黑像素佔比”這類指標代替（本次就是被它蒙過）。
  • 後續如再改動 scale_rotate90() 結構，必須確保 R/B 交換在整個鏈路中總共只做一次。

7. 相關文件

  • 設備：/home/lvgl_demo/lvgl_demo/extern/miniretro/miniretro.c（scale_rotate90()）
  • 本地：ssh_tools/_tmp/miniretro.c、抓幀腳本 ssh_tools/gba_capture.py
