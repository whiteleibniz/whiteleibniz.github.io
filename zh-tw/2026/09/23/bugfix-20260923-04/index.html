bugfix_20260923_04 — GBA 改用 miniretro 後仍然黑屏（video_cb 硬編碼分辨率丟幀）

現象：GBA 啟動方式改成 miniretro + mgba_libretro.so 後，核心能加載、進程在跑，但屏幕全黑。
根因層：miniretro 前端幀回調 video_cb（渲染管線）。
修復工作量：extern/miniretro/miniretro.c（本項與「條紋」修復合計 +81/-13，見 bugfix_20260923_05）。
文件名：bugfix_20260923_04_GBA改用miniretro後仍黑屏.md
關聯提交：（待提交後回填）
日期：2026-09-23

現象

  1. GBA 啟動已改為 miniretro extern/miniretro/mgba_libretro.so <rom> ...（見 bugfix_20260923_03）。
  2. 冒煙測試顯示核心加載正常：core: mGBA 0.11.0、遊戲已加載 240x160, 59.73 fps。
  3. 但真實進入遊戲時全屏黑，進程存活、無崩潰日誌。
  4. 對照：同一個 miniretro 跑 FC（fceumm_libretro.so，256×240）畫面完全正常。

線索：核心加載成功卻黑屏 → 幀數據在渲染環節被丟掉了，且只發生在 GBA 這一路。

影響範圍

  • 受影響：所有 240×160 的核心（GBA / mGBA）。
  • 不受影響：FC（256×240）——仍走原路徑，行為不變。
    （本次改動對 FC 透明，共用的 miniretro 可安全改。）

根因

miniretro.c 的幀回調 video_cb 把分辨率硬編碼成 FC 的尺寸：

mGBA 輸出的是 240×160（日誌實錘：遊戲已加載 240x160）。
240 != 256 → 條件成立 → return，每一幀都在進入繪製前被丟棄，fb_buf 從不刷新 → 黑屏。

此外，同函數下面的 scale_rotate90() 還寫死了源尺寸 FC_W/FC_H，即便放行也會用錯尺寸。

定位過程

  1. 確認鏈路：冒煙測試證明 core 加載正常、ROM 正確、fb0 已 mmap、輸入設備已打開 → 排除”沒啟動/沒加載”。
  2. 找到客觀指標：用”fb0 非黑像素佔比”量化——黑屏時應 ≈ 0。
  3. 讀源碼：在 miniretro.c 裡 grep 分辨率相關符號，if(width != FC_W || height != FC_H) return; 一眼可見。
  4. 彎路（錯方向）：一開始懷疑”核心沒加載 / 像素格式不對”，但日誌已證核心加載成功；
    真正的原因是尺寸守衛，而不是格式。
  5. 驗證：放行 240×160 後重編，受控自測 fb0 非黑像素佔比從 ≈0 變為 0.559 → 畫面確實出來了。

解決辦法

extern/miniretro/miniretro.c：

  1. 放行 GBA 分辨率：

  2. scale_rotate90() 改用傳入的動態寬高（out_h = out_w * rot_canvas_h / rot_canvas_w），
    不再引用 FC_W/FC_H。

  3. 補 0RGB1555 兜底分支（核心未主動聲明像素格式時的默認值；mGBA 實際用 RGB565，分支 2）。

  4. 重編：cd extern/miniretro && sh build.sh（該目錄無 Makefile，用 build.sh）。

驗證

  • 受控自測（設備端單獨跑 miniretro mgba_libretro.so <rom>）：
    fb0 非黑像素 = 515088 / 921600，佔比 0.559，日誌 core 輸出像素格式 = 2（RGB565）。
    → 畫面確實渲染出來了（此前黑屏時應 ≈0）。
  • 用戶實機確認：”有圖像了” —— 但仍描述為”撕裂狀”，轉入 bugfix_20260923_05。

經驗教訓

  1. 複用別平臺的前端時，硬編碼的分辨率/尺寸守衛是頭號殺手。
    不同 libretro 核心的輸出分辨率不同（fceumm 256×240、mGBA 240×160），
    前端任何”== 某尺寸才處理”的寫法都會靜默丟幀。
  2. **”核心加載成功”不等於”有畫面”**：加載日誌只證明 retro_load_game 成功，
    幀要經過 video_cb 才能上屏，中間任何一次”靜默 return”都會黑屏且不報錯。
  3. **量化指標（非黑像素佔比）很好用，但只能證明”有畫面”，證明不了”畫面正確”**——
    它能抓出黑屏，抓不出錯位/條紋。判”畫面對不對”必須人眼看圖。
