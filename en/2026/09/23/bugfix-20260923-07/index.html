GBA Screen Stutters and Hangs When Exiting a Game

wlb
2026-09-23
bugfix, 模拟器

bugfix_20260923_07 — The GBA screen stutters / hangs when exiting a game

  • Date: 2026-09-23
  • Module: GBA game page / miniretro.c exit path + lv_pages/gba_game_page.c
  • Impact: All GBA game exits, as well as FC game exits (shared miniretro)

1. Problem symptoms

When pressing the 买单 (pay-the-bill) key (116) to exit a game, the picture freezes / becomes garbled for a few seconds before returning to the list, sometimes leaving half a game frame on screen.

2. Scope of impact

  • GBA / FC game exit back to the list
  • Subsequent LVGL rendering (the residue stays smeared in place until that area is redrawn)

3. Root cause analysis

Three causes are superimposed:

  1. miniretro has no SIGTERM handling
    The parent process’s gba_exit_to_list() only sends kill(pid, SIGTERM) and then falls back to SIGKILL after 120ms.
    SIGTERM’s default behavior is to kill the process directly → the main loop’s cleanup section never executes (fb_restore/munmap are all skipped).
  2. The fb stays on the flipped page
    Double buffering uses FBIOPAN_DISPLAY to switch pages; when killed, the foreground page stays at yoffset=1280 (page 1),
    while LVGL only draws to page 0 → the screen keeps showing that old game frame on page 1.
    Measured evidence: after kill -TERM, reading FBIOGET_VSCREENINFO yields yoffset=1280 (0 after the fix).
  3. LVGL only refreshes dirty areas
    A known project conclusion: LVGL only flushes self-drawn areas and does not clear the whole screen. The pixels written directly to fb0 by miniretro are not in LVGL’s dirty areas,
    so even if drawing resumes, the residue cannot be erased.
    In addition, the game picture has 100px letterbox black bars at the top and bottom (out_w=720 → out_h=1080) that are not part of the output area; failing to clear the screen before starting leaves the last UI frame from LVGL, looking like a “garbled band”.

4. Fix

  • miniretro.c: add on_quit_signal(), install SIGTERM/SIGINT handlers that only set quit=1, letting the main loop exit naturally and complete cleanup.
  • miniretro.c: add fb_restore() — use FBIOPAN_DISPLAY to return yoffset to 0 and clear the entire virtual video memory.
    Call it once each at exit cleanup and before entering the main loop (the latter incidentally clears residue in the letterbox area).
  • gba_game_page.c: widen the grace period of gba_exit_to_list() from 120ms to 250ms,
    leaving time for a graceful exit, with SIGKILL still as the fallback on timeout.

5. Verification method and results

Controlled device-side test (read the fb state immediately after kill -TERM):

The log showing [miniretro] 退出 proves that cleanup (including fb_restore()) was reached instead of being interrupted by SIGKILL.

6. Regression risks

  • The SIGKILL fallback path is retained: if the child process hangs abnormally, force-kill it after 250ms, in which case the fb is not reset,
    but the full-screen redraw of gba_timer_cb + an LVGL refresh still saves the day (only 130ms more delay than before the fix).
  • Clearing the screen is a memset of the entire virtual video memory (3 pages × 1280 rows), about 11MB, a one-time cost that is negligible.
